# ΦilosΦaira: развёртывание на Windows 10 (в том числе в виртуалке под Windows 7)

Расклад машин, из которого всё следует:

| Машина | Что на ней | Почему так |
|---|---|---|
| **Windows 10 (виртуалка)** | PostgreSQL, Node, узел, Chrome 131, серверная приёмка | Win7 не тянет ни Node ≥ 14, ни Chrome ≥ 110, ни PostgreSQL ≥ 11 |
| **Windows 7 (хозяин)** | браузер со страницей | ему довольно Chrome 109 или Firefox ESR 115 |

Проверено по коду: возможностей новее Chrome 109 / Firefox ESR 115 в приложении
нет (ни `toSorted`, ни `structuredClone`, ни `:has()`), база грузится через
`fetch` — значит браузер Win7 страницу потянет. Это то же наблюдение, что и в
`philosphaira-ubuntu.md`, и оно не зависит от того, что за система внутри
виртуалки.

Если Windows 10 у вас настоящая, а не виртуальная, — всё написанное годится
как есть; раздел 1 тогда можно пропустить.

> ### Стоит ли вообще брать Windows 10 виртуалкой
>
> Скажу честно, раз выбор всё равно ваш. Если виртуалка нужна в любом случае,
> Ubuntu обходится **втрое дешевле** и умеет больше:
>
> | | Ubuntu 24 | Windows 10 |
> |---|---|---|
> | памяти | 2 ГБ довольно | 4 ГБ минимум, 6 спокойнее |
> | диска | 20 ГБ | 60 ГБ (одна система ~30) |
> | приёмка приложения | работает вся | не портирована (§9) |
> | лицензия | не нужна | нужна |
> | прогнано живьём | да | нет |
>
> Windows 10 оправдана, если она уже есть и нужна для другого, если привычнее
> `Проводник` и `Диспетчер задач`, или если однажды захочется поставить
> проект на настоящую, не виртуальную машину. Ради одного лишь ΦilosΦaira
> я бы взял Ubuntu по соседней инструкции.

| Что нужно | Версия | Почему именно так |
|---|---|---|
| Windows 10 | x64, 1809 или новее | ниже нет `winget`, `tar` и `Get-NetTCPConnection` |
| Node | 22 | на 18 не встанет `express` 5; на 24 приёмка не учреждалась |
| PostgreSQL | 16 | установщики EDB проверены на Server 2019/2022 — десктопный Win10 им равнозначен |
| Chrome | ровно 131.0.6778.204 | на этой сборке учреждены эталоны `css_probe`, а вычисленные стили машинно-зависимы |
| PowerShell | 5.1 (встроенный) | 7.x тоже годится |

**Только x64.** Единственная нативная зависимость проекта — `argon2`: её
готовые сборки выкладываются под Windows x86-64. На 32-разрядной системе
`npm` пойдёт собирать из исходников и потребует Visual Studio Build Tools —
полтора гигабайта ради одной библиотеки.

## 0. Порядок целиком: пять команд

Всё, описанное ниже, делает `philos-win10.ps1`. Если ничего не менять,
хватит пяти команд — и разделы 3–5 тогда читаются **ради доводов**, а не
ради действий:

```powershell
# PowerShell от имени администратора — для «установить», «доступ» и «служба»
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass

.\philos-win10.ps1 установить                  # Node 22, PostgreSQL 16, Chrome 131
.\philos-win10.ps1 развернуть C:\philosphaira.tar.xz
.\philos-win10.ps1 доступ                      # брандмауэр — ТОЛЬКО для виртуалки
.\philos-win10.ps1 пуск                        # оба процесса: узел и работник
.\philos-win10.ps1 состояние                   # проверить, что оба живы
```

**`доступ` нужен, если страницу открывают не в самой машине.** На Ubuntu
брандмауэр по умолчанию пропускает всё, и вопроса не возникает вовсе;
Windows входящие соединения по умолчанию **не пускает**. Узел при этом
поднимется, порт займёт, `состояние` скажет «работает» — а с хозяйской
машины страница не откроется, и чинить пойдут сервер.

**Что делает `развернуть`** — распаковку, `npm install` в двух местах, две
базы, `%USERPROFILE%\philos.env`, миграции, семя графа, первую раскладку
**и первого администратора**. Пароль администратора он спросит с клавиатуры
без эха, если не задан `BOOTSTRAP_ADMIN_PASSWORD`; логин по умолчанию
`admin`, почта `admin@example.invalid` — свои задаются переменными (§4.3).

**Чего он не делает:** не заводит второй шаг (§5.4 — обязателен, иначе у
администратора срезаны права) и не ставит автозапуск (`служба`, §6).

Остальные действия: `стоп`, `журнал`, `адрес`, `доступ`, `служба`, `приёмка`.

> **Дальше — то же самое вручную, с доводами.** Каждый раздел помечен, делает
> ли его скрипт: так видно, что уже пройдено, а что осталось на вас.

## 1. Ресурсы виртуалки и сеть

Пропустите этот раздел, если Windows 10 у вас настоящая.

### Ресурсы

| | Сколько | Почему столько |
|---|---|---|
| память | **4 ГБ**, лучше 6 | сама система берёт около 2; сверх того PostgreSQL, два процесса Node и — во время приёмки — Chrome в безголовом ладу |
| ядра | 2, лучше 4 | приёмка водит браузер и держит узел разом |
| диск | **60 ГБ** | Windows 10 ~30, PostgreSQL ~1, `node_modules` в двух местах ~80 МБ, Chrome 131 ~300 МБ, база с графом невелика |
| проброс 3D | не нужен | граф рисуется на Canvas 2D |

**Приёмка в виртуалке идёт заметно дольше.** Серверная — двадцать одна проба,
из них три водят браузер. На железе это минут двадцать; при 4 ГБ и двух ядрах
закладывайте вдвое. Если Chrome начнёт падать без внятного сообщения — почти
всегда это память, а не проект.

### Сеть: мост или NAT

**Мост (bridged)** — проще всего. Виртуалка получает адрес в домашней сети,
и с Windows 7 страница открывается по нему напрямую:

```
http://192.168.1.50:8814/
```

Адрес покажет `.\philos-win10.ps1 адрес` — он распознаёт виртуалку по
производителю платы и называет оба случая.

**NAT** — виртуалка снаружи не видна, нужен **проброс порта**. В VirtualBox:
`Настройки → Сеть → Дополнительно → Проброс портов`, правило
`TCP, хост 127.0.0.1:8814 → гость 8814`. После этого на Windows 7 страница
живёт по адресу `http://127.0.0.1:8814/` — на самой хозяйской машине.

Узел слушает **все интерфейсы** (`listen(порт)` без адреса в
`server/src/http/server.js`), так что и мост, и NAT работают без правки
настроек проекта.

### Брандмауэр Windows — главное отличие от Ubuntu

```powershell
.\philos-win10.ps1 доступ     # от имени администратора
```

Заводит правило `Philosphaira-HTTP` на текущий `PORT`, **только для частной
сети**. Открывать порт в «общедоступной» значило бы пускать в него кафе и
вокзал; виртуалка в мосте или NAT попадает именно в частную. Если сеть
помечена иначе, скрипт скажет об этом и назовёт команду:

```powershell
Set-NetConnectionProfile -InterfaceIndex <N> -NetworkCategory Private
```

Правило **пересоздаётся**, а не правится: порт живёт в `philos.env` и может
смениться, а старое правило на прежний порт осталось бы висеть. `состояние`
проверяет, что правило есть и что оно на тот самый порт.

### Как занести архив внутрь

* **Общая папка** — в VirtualBox `Настройки → Общие папки`, внутри виден как
  сетевой диск. Нужны Guest Additions.
* **Перетаскиванием** — если включено двустороннее в настройках виртуалки.
* **По сети** — если мост: расшарить папку на Windows 7 и открыть изнутри по
  `\\192.168.1.10\share`.

### Чем управлять изнутри

Отдельный SSH ставить не нужно. Довольно окна самой виртуалки: `PowerShell`
через `Win+X`. Если хочется полноэкранной работы — на Windows 10 **Pro**
работает `Подключение к удалённому рабочему столу`, и `mstsc` на Windows 7
есть штатно; на **Home** удалённого стола нет, окна виртуалки довольно.

## 2. Про `Set-ExecutionPolicy` и почему она в первой строке

Windows по умолчанию не исполняет неподписанные `.ps1`. Команда выше
снимает запрет **только для текущего окна** — `-Scope Process`. Постоянно
менять политику машины не нужно и не стоит: следующее окно снова будет
строгим, и это правильно.

Если и это запрещено политикой организации, есть обход без изменения
настроек вовсе:

```powershell
powershell -ExecutionPolicy Bypass -File .\philos-win10.ps1 состояние
```

## 3. Установка (один раз) — делает `установить`

### 3.1. Node 22

```powershell
winget install --id OpenJS.NodeJS.LTS
```

**PATH обновляется только в новом окне.** После установки `node -v` в том же
окне PowerShell, скорее всего, ответит «не найдено». Скрипт подтягивает PATH
из реестра сам, но если он всё-таки сообщил «Node не встал» — закройте окно
и откройте заново. Это не поломка.

### 3.2. PostgreSQL 16

```powershell
winget install --id PostgreSQL.PostgreSQL.16 `
  --override "--mode unattended --superpassword postgres --serverport 5432 --locale C"
```

**Пароль роли `postgres` задаётся здесь и больше нигде не спрашивается.**
Скрипт ходит в СУБД именно им. Если СУБД у вас уже стояла и пароль другой —
передайте его перед запуском:

```powershell
$env:POSTGRES_PASSWORD = 'ваш-пароль'
```

**Пользователя `postgres` в системе Windows нет.** В Ubuntu скрипт ходит
`sudo -u postgres psql` — здесь такого пользователя не существует вовсе,
установщик заводит только роль внутри СУБД. Отсюда и пароль: другого пути
нет.

**`psql` не попадает в PATH.** Он лежит в
`C:\Program Files\PostgreSQL\16\bin`. Скрипт ищет его сам — сперва в PATH,
потом по этому пути, потом обходом папки. Для ручной работы удобно добавить
эту папку в PATH самому.

### 3.3. Chrome 131 — именно эта сборка

```powershell
cd $HOME
npx --yes @puppeteer/browsers install chrome@131.0.6778.204
```

Ставится **отдельная копия** в `%USERPROFILE%\chrome\win64-131.0.6778.204`,
а не системный браузер. Довод простой: системный Chrome обновляется сам, и
однажды утром `css_probe` разойдётся с эталоном без всякой правки кода.
Отдельная копия не обновляется никогда.

Системный браузер для **просмотра** страницы годится любой — ограничение
касается только приёмки.

## 4. Развёртывание проекта — делает `развернуть`

### 4.1. Распаковка и зависимости

```powershell
tar -xf C:\philosphaira.tar.xz -C $HOME      # tar есть в Win10 с 1803
cd $HOME\philosphaira
npm install                                   # приборы приёмки приложения
cd server; npm install                        # сам узел
```

Скрипт принимает и `.zip`, и `.tar.xz`, и просто каталог. Внутри архива он
ищет не корень, а папку, где лежит `server\package.json`, — архив бывает и с
обёрткой, и без.

### 4.2. Две базы, а не одна

```sql
CREATE DATABASE philos      ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;
CREATE DATABASE philos_test ENCODING 'UTF8' LC_COLLATE 'C' LC_CTYPE 'C' TEMPLATE template0;
CREATE ROLE philos LOGIN PASSWORD 'philos';
ALTER DATABASE philos      OWNER TO philos;
ALTER DATABASE philos_test OWNER TO philos;
```

**Испытательная отдельно, и это не придирка:** `db_probe` откатывает
`philos_test` до пустого места. Одна база на оба дела — потерянные данные
при первом же прогоне приёмки.

**Про локаль — расхождение с Ubuntu, и существенное.** Там указано
`--locale=C.UTF-8`. В Windows-сборке PostgreSQL такой локали нет; годится
`LC_COLLATE 'C'` с кодировкой `UTF8`. Важно здесь ровно одно: единственность
логина держится на `lower()`, а в **однобайтовой** `C` вызов `lower('ИВАН')`
вернёт `ИВАН` — и `ИВАН` с `иван` заведутся как двое разных. Спасает
кодировка `UTF8`: в ней `lower()` работает по Юникоду независимо от
сортировки. Поэтому скрипт после создания базы **прямо спрашивает у СУБД**
её кодировку и останавливается, если это не `UTF8`. Проверка дешёвая, а
ошибка тихая.

### 4.3. Переменные окружения

Файл `%USERPROFILE%\philos.env`, тот же синтаксис `КЛЮЧ=значение`, что и в
Ubuntu, — чтобы один файл годился на обеих системах: переносят его обычно
вместе с базой.

```
DATABASE_URL=postgres://philos:philos@127.0.0.1:5432/philos
MFA_SECRET_KEY=<32 случайных байта в base64>
PORT=8814
# PUBLIC_URL=http://адрес-в-сети:8814   # корень ссылок в письмах
# NODE_ENV=production                   # cookie только по HTTPS — нужен ставень
```

**Права.** Аналога `chmod 600` в Windows нет: файл наследует права папки
профиля. Скрипт снимает наследование и оставляет владельца:

```powershell
icacls $HOME\philos.env /inheritance:r /grant:r "$($env:USERNAME):(R,W)"
```

Без этого `MFA_SECRET_KEY` читает любой пользователь машины.

**СОХРАНИТЕ `MFA_SECRET_KEY` ВНЕ МАШИНЫ.** Потеряете — потеряете все TOTP:
второй шаг у всех перестанет сходиться, и войти не сможет никто, включая
администратора.

Свои логин и почту администратора задают перед `развернуть`:

```powershell
$env:BOOTSTRAP_ADMIN_LOGIN = 'ivan'
$env:BOOTSTRAP_ADMIN_EMAIL = 'ivan@example.org'
```

## 5. Первый запуск (5.1–5.3 — по одному разу за всю жизнь базы)

### 5.1. Схема

```powershell
cd $HOME\philosphaira\server
npm run migrate
npm run migrate:status
```

### 5.2. Семя графа

```powershell
npm run graph:import
```

Отказ «граф не пуст» — **защита, а не поломка**: повторный ввоз затёр бы
правки. Осознанный повтор — `$env:ALLOW_GRAPH_REIMPORT = '1'`.

### 5.2а. Первая раскладка

```powershell
node scripts/relayout.mjs --применить
```

Раскладка хранится в базе (миграции 013–014). Прежде каждый клиент считал её
сам, и выходила она у всех разная: один и тот же d3 в разных движках
расходится с медианой около 65 px. Пока человек один — незаметно; как только
двое, общий язык про «вон тот сгусток справа» пропадает.

### 5.3. Первый администратор

```powershell
$env:BOOTSTRAP_ADMIN_PASSWORD = 'не-короче-двенадцати'
npm run bootstrap-admin
$env:BOOTSTRAP_ADMIN_PASSWORD = $null
```

Скрипт спрашивает пароль с клавиатуры без эха, если переменная не задана, и
стирает её за собой.

### 5.4. Второй шаг администратора — ОБЯЗАТЕЛЕН

Скрипт этого **не делает**, и сам `bootstrap-admin` об этом предупреждает:

> СЛЕДУЮЩИЙ ШАГ: войти и завести второй шаг — без него опасные права
> срезаны, и назначить второго администратора нельзя.

Войдите на `http://127.0.0.1:8814/`, откройте настройки учётной записи и
заведите TOTP. До этого администратор — administrator лишь по названию.

### 5.5. Проверка на месте

```powershell
.\philos-win10.ps1 состояние
```

Показывает: отвечает ли СУБД, живы ли **оба** процесса, что отдаёт HTTP и
сколько в исходящих неразосланного.

## 6. Автозапуск — делает `служба`

```powershell
.\philos-win10.ps1 служба     # от имени администратора
```

**Две задачи, а не одна** — по той же причине, что и в `пуск` (см. §7).

**При входе, а не при загрузке.** Задача при загрузке шла бы от `SYSTEM`, а
`philos.env` лежит в профиле человека и права на него сняты до одного
владельца. Вход в систему — честная граница владения ключом.

Смотреть и снимать:

```powershell
Get-ScheduledTask -TaskName Philosphaira*
Unregister-ScheduledTask -TaskName Philosphaira, Philosphaira-Worker -Confirm:$false
```

## 7. Работник уведомлений — ВТОРОЙ ПРОЦЕСС, И ОН НУЖЕН ВСЕГДА

Цепочка живого отклика:

```
коммит → извещение в исходящие → РАБОТНИК публикует в шину
       → узел рассылает по сокетам → страница берёт приращение
```

Нет работника — нет второго звена, и чужая правка **не доходит до открытых
страниц вовсе**. Извещение в шину идёт до почты и независимо от неё: работник
нужен не «когда заведёте почту», а всегда.

Коварство в том, что его молчание **не видно на глаз**: сервер отвечает,
страница работает, правки сохраняются. Поэтому `состояние` показывает его
отдельной строкой и тут же считает неразосланное в `outbox`.

## 8. Бессерверный режим

Если сервер не нужен вовсе — граф работает и без него:

* `source\philosophy_graph_v3.html` открывается **двойным щелчком**, без
  Node и без базы. Все 718 концепций, 2720 связей, метрики, поиск пути,
  статистика — на месте;
* собранное дерево `app\` требует статического сервера (модульные ввозы по
  `file://` браузер не пускает):

```powershell
cd $HOME\philosphaira\app
python -m http.server 8080
```

Пропадает ровно то, что даёт сервер: учётные записи, коммиты, модерация,
живое обновление.

## 9. Приёмка

```powershell
.\philos-win10.ps1 приёмка
```

Гонит **21 пробу серверного слоя** на испытательной базе. `DATABASE_URL`
подменяется на `philos_test` жёстко, что бы ни стояло в окружении: `db_probe`
откатывает базу до пустого места, и одна забытая переменная стоила бы
рабочих данных.

**Чем это не вызов `server/accept.sh`.** Тот перечисляет пробы и складывает
двадцать одну однобуквенную переменную; в самом файле записано, что до
10 сентября 2026 там были две ошибки — одна буква присваивалась дважды
(провал раскладки маскировался), другая не входила в сумму (надпись
«КРАСНАЯ» при коде возврата 0). В PowerShell-варианте список проб — **данные**,
и такая ошибка по устройству невозможна: складывается то же, что перечислено.

**Приёмка приложения** (`tools/accept.sh`: 165 утверждений, обход в 320
снимков, `compare`, `probe6–8`, `css_probe`, `blind_probe` и сличение сторон)
на Windows **не портирована**. Она длится около часа, держит присмотр за
статическим сервером и водит браузер тремя частями; переписывать её значило
бы завести второе место, где записана одна и та же последовательность, — а
в этом проекте такое уже кончалось расхождением. Если она нужна, есть три
пути: Git Bash (`winget install Git.Git`, затем
`bash tools/accept.sh`), WSL2 или отдельная машина с Ubuntu по
`philosphaira-ubuntu.md`.

Отдельные приборы приложения идут на Windows без обвязки:

```powershell
$env:CHROME    = "$HOME\chrome\win64-131.0.6778.204\chrome-win64\chrome.exe"
$env:PUPPETEER = "$HOME\philosphaira\node_modules\puppeteer-core"
cd $HOME\philosphaira
node tools/checks/check_modules.mjs
node tools/checks/build_invariant.mjs
python tools\serve.py app 8711          # и затем, в другом окне:
$env:BASE = 'http://127.0.0.1:8711/'
node tools/probes/assert_probe.mjs index.html
```

## 10. Правка исходника и пересборка

Порядок тот же, что везде (readme §5), и на Windows не меняется:

```powershell
node tools/maps/map_globals.mjs source\philosophy_graph_v3.html mapping\globals_map_v3.json
node tools/remap.mjs проверить          # сущности без модуля
#                                       # вписать их в decisions\assign_names.json
node tools/remap.mjs собрать
```

Кириллические слова команд (`проверить`, `собрать`, `применить`) PowerShell
передаёт в Node без затей — в отличие от `bash`, который не принимает
кириллических **имён переменных** вовсе.

## 12. Грабли, каждая из которых уже кого-то стоила

| Признак | Причина | Лечение |
|---|---|---|
| `.ps1 не может быть загружен, так как выполнение сценариев отключено` | политика по умолчанию | `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| `node` не найден сразу после установки | PATH обновляется только в новом окне | закрыть и открыть PowerShell |
| `psql` не найден | EDB не кладёт его в PATH | `C:\Program Files\PostgreSQL\16\bin` |
| `password authentication failed for user "postgres"` | пароль роли задан не `postgres` | `$env:POSTGRES_PASSWORD = '…'` до запуска |
| `argon2` собирается из исходников и падает | нет готовой сборки под эту связку | x64 и Node 22; иначе Visual Studio Build Tools |
| Вошли — и сразу гость | `NODE_ENV=production` по HTTP: cookie с `Secure` не сохраняется | убрать переменную |
| Страница открылась, живого обновления нет | `WS_ORIGINS` задан и не совпадает с адресом | убрать переменную |
| Узел не поднялся, в журнале `EADDRINUSE` | порт занят прежним узлом | `стоп`, затем `пуск`; скрипт проверяет порт заранее |
| `css_probe` разошёлся | другая сборка браузера | ровно 131.0.6778.204 из `%USERPROFILE%\chrome` |
| Рабочая база опустела | приёмка гонялась на боевом `DATABASE_URL` | всегда `philos_test`; скрипт подменяет жёстко |
| `graph:import` отказал | граф не пуст — это защита, а не поломка | так и задумано; повтор — `ALLOW_GRAPH_REIMPORT=1` |
| Логин `ИВАН` и `иван` завелись оба | база создана не в `UTF8` | пересоздать с `ENCODING 'UTF8' TEMPLATE template0` |
| `npm start` не поднял базу и не завёл людей | запуск ничего не готовит нарочно | шаги 5.1–5.3 руками |
| В журнале пусто, а узел молчит | вывод ошибок идёт в отдельный файл | смотреть и `server.log.err` тоже; `журнал` показывает оба |
| В самой машине страница открывается, с Windows 7 — нет | брандмауэр Windows не пускает входящие | `.\philos-win10.ps1 доступ` от администратора |
| `доступ` отработал, а снаружи всё равно нет | сеть помечена «общедоступной», правило на неё не действует | `Set-NetConnectionProfile … -NetworkCategory Private` |
| Мост настроен, адрес не пингуется | у виртуалки адрес `169.254.*` — DHCP не дал | проверить, что мост привязан к настоящей плате хозяина |
| NAT: `адрес` показывает `10.0.2.15`, а он не открывается | это внутренний адрес NAT, снаружи не виден | проброс порта 8814 в настройках виртуалки, затем `127.0.0.1:8814` на хозяине |
| Chrome в приёмке падает без сообщения | виртуалке не хватает памяти | 6 ГБ; либо гонять приёмку без пробы страницы |
