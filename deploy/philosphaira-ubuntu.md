# ΦilosΦaira: развёртывание на виртуальной Ubuntu 24, управление из Windows 7

Расклад машин, из которого всё следует:

| Машина | Что на ней | Почему так |
|---|---|---|
| **Ubuntu 24 (виртуалка)** | PostgreSQL, Node, сервер, Chrome 131, вся приёмка | вся оснастка проекта — `bash`, `python3`, `setsid`, кириллические имена в скриптах |
| **Windows 7 (хост)** | браузер со страницей, PuTTY с командной строкой | Node ≥14 и Chrome ≥110 на Win7 не идут вовсе |

Проверено по коду: возможностей новее Chrome 109 / Firefox ESR 115 в приложении нет (ни `toSorted`, ни `structuredClone`, ни `:has()`), база грузится через `fetch` — значит браузер Win7 страницу потянет.

---

> **ЕСТЬ СКРИПТ.** Всё, описанное ниже, делает `philos-ubuntu.sh` одной
> командой: `установить`, `развернуть <архив|каталог>`, `пуск`, `стоп`,
> `состояние`, `служба`, `приёмка`. Инструкцию стоит прочесть ради доводов —
> почему две базы, почему именно эта сборка Chrome, почему процессов два.
> Скрипт проверен прогоном на Ubuntu 24.04: развёртывание из каталога,
> 14 миграций, семя, раскладка, администратор, подъём и остановка обоих
> процессов.

## 1. Ресурсы виртуалки

Выключите её и задайте:

- **память 4096 МБ** (минимум 3072 + подкачка 2 ГБ; пик даёт не сервер, а Chrome на полном обходе);
- **ядер 2** (на одном ядре обход растянется втрое);
- **диск — свободных 6 ГБ**: `node_modules` двух проектов, Chrome 131, PostgreSQL, дампы.

### Сеть

Выберите одно из двух.

**NAT с пробросом портов** — виртуалка остаётся невидимой в домашней сети, обращение идёт на `127.0.0.1` хоста. В VirtualBox: *Настройки → Сеть → Проброс портов*, три правила:

| Имя | Порт хоста | Порт гостя |
|---|---|---|
| ssh | 2222 | 22 |
| philos | 8814 | 8814 |
| static | 8711 | 8711 |

**Мост (bridged)** — виртуалка получает адрес в домашней сети, обращение по нему. Удобнее, если захотите зайти ещё и с телефона. Адрес узнаётся в госте: `ip -4 addr show`.

Дальше в тексте адрес страницы обозначен как `АДРЕС`: при NAT это `127.0.0.1`, при мосте — адрес виртуалки.

### Доступ по SSH

В госте:

```bash
sudo apt update && sudo apt install -y openssh-server
sudo systemctl enable --now ssh
```

С Win7 ходите PuTTY: при NAT — `127.0.0.1` порт `2222`, при мосте — адрес виртуалки, порт `22`.

## 2. Установка (один раз)

### 2.1. Node 22

Не берите Node из репозиториев Ubuntu (там 18.19): `argon2` 0.45 и `puppeteer-core` 25 на нём — лотерея с готовыми сборками.

```bash
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs
node -v            # ждём v22.x
```

### 2.2. PostgreSQL, Python, мелочь

```bash
sudo apt install -y postgresql python3 python3-venv curl unzip git
```

### 2.3. Chrome 131 — именно эта сборка

`puppeteer-core` браузеров не качает, а эталоны учреждены на 131.0.6778.204. Другая сборка даёт расхождение `css_probe`, и это не дефект проекта — вычисленные стили машинно-зависимы.

```bash
cd ~
npx @puppeteer/browsers install chrome@131.0.6778.204
```

Библиотеки, без которых Chrome на безголовой Ubuntu не стартует (и молчит невнятно):

```bash
sudo apt install -y libnss3 libatk1.0-0 libatk-bridge2.0-0 libcups2 libdrm2 \
  libxkbcommon0 libxcomposite1 libxdamage1 libxfixes3 libxrandr2 \
  libgbm1 libpango-1.0-0 libasound2t64
```

`libasound2t64` — имя именно для 24.04; старое `libasound2` не найдётся.

## 3. Развёртывание проекта

### 3.1. Распаковка и зависимости

```bash
cd ~
unzip philosphaira.zip          # получится ~/philosphaira
cd philosphaira
npm install                     # acorn, d3, eslint-scope, puppeteer-core
cd server && npm install        # express, pg, ws, argon2
cd ..
```

`argon2` нативный: под Linux x64 берётся готовая сборка, компилятор не понадобится.

### 3.2. Две базы, а не одна

**Приёмка сервера уничтожает базу**, на которую указывает `DATABASE_URL`: `db_probe` откатывает миграции до пустого места (`while (!мигр('down')…)`). Поэтому испытательная база заводится сразу, отдельно от рабочей.

```bash
sudo -u postgres psql -c "CREATE ROLE philos LOGIN PASSWORD 'придумайте-пароль'"
sudo -u postgres createdb philos      --owner=philos --locale=C.UTF-8 --template=template0
sudo -u postgres createdb philos_test --owner=philos --locale=C.UTF-8 --template=template0
```

Локаль обязана сворачивать кириллицу: единственность логина и почты держится на `lower()`, а в голой локали `C` строка `ИВАН` не станет `иван`. Проверяет `auth_probe`. В glibc 2.39 локаль `C.UTF-8` встроена, генерировать её не надо.

### 3.3. Переменные окружения

Заведите `~/philos.env` — **без `export`**, в формате `КЛЮЧ=значение` (так его понимает и `systemd`, и оболочка):

```ini
DATABASE_URL=postgres://philos:придумайте-пароль@127.0.0.1:5432/philos
MFA_SECRET_KEY=<сюда вывод команды ниже>
PORT=8814
```

Ключ второго шага:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
chmod 600 ~/philos.env
```

**Сохраните `MFA_SECRET_KEY` вне виртуалки.** Потеряете ключ — потеряете все заведённые TOTP.

Чего в этом файле быть **не должно**:

- `NODE_ENV=production` — включает `безопасныеCookie`, cookie сессии уходит с флагом `Secure`, и по обычному HTTP браузер её не сохранит. Вы войдёте и тут же окажетесь гостем, без внятной ошибки.
- `WS_ORIGINS` — `null` означает «не проверять». Если задать, там должен стоять ровно тот origin, по которому вы открываете страницу, вместе со схемой и портом; иначе страница откроется, а живые соединения будут молча отвергаться.

Для работы в оболочке подхватывайте файл так:

```bash
set -a; . ~/philos.env; set +a
```

## 4. Первый запуск (шаги 4.1–4.3 — по одному разу за всю жизнь базы)

```bash
cd ~/philosphaira/server
set -a; . ~/philos.env; set +a
```

### 4.1. Схема

```bash
npm run migrate
npm run migrate:status
```

Повторный накат безопасен: применяется только то, чего нет.

### 4.2. Семя графа

```bash
npm run graph:import
```

Кладёт шесть наборов из `app/data` в `graph_entities`. Работает **только на пустом графе**: `importSet` пишет с `ON CONFLICT DO UPDATE`, и повтор перезаписал бы серверные правки семенем. Осознанный повтор — `ALLOW_GRAPH_REIMPORT=1`.

### 4.2а. Первая раскладка графа

```bash
npm run relayout                 # посчитать и ПОКАЗАТЬ, насколько сдвинет
npm run relayout -- --применить  # записать
```

**Шаг появился вместе с хранимой раскладкой (миграции 013–014) и обязателен
после переноса семени.** Прежде каждый клиент считал раскладку сам — и
выходила она у всех разная: один и тот же d3 в разных движках даёт
расхождение с медианой около 65 px. Пока человек один, это незаметно; как
только их двое, «вон тот сгусток справа» перестаёт быть общим языком.

Без применения раскладки граф откроется, но координаты будут считаться на
месте и у каждого свои.

Первый вызов НИЧЕГО НЕ ПИШЕТ — только показывает меру расхождения; это
заслон от случайной перекладки. Дальше раскладка доращивается сама при
каждом утверждённом коммите, полная перекладка нужна лишь изредка.

### 4.3. Первый администратор

```bash
BOOTSTRAP_ADMIN_LOGIN=nyanko \
BOOTSTRAP_ADMIN_EMAIL=вы@ваша.почта \
BOOTSTRAP_ADMIN_PASSWORD='пароль-от-12-знаков' \
npm run bootstrap-admin
```

Пароль настоящий, требования те же, что при обычной регистрации: не короче 12 знаков, без пробелов по краям, не из списка частых. Почта считается подтверждённой сразу — оператор, держащий в руках `DATABASE_URL` и ключ MFA, доказал владение сильнее письма.

**Второй шаг администратор заводит сам**, из панели. До этого у него срезаны опасные права, включая назначение второго администратора.

### 4.4. Проверка на месте

```bash
npm start
```

Ответом будет `ΦilosΦaira поднята: http://127.0.0.1:8814/`. Адрес в сообщении — только текст: в `server.js:22` стоит `сервер.listen(порт)` без адреса, узел слушает все интерфейсы. Ничего править не надо.

Файрвол в Ubuntu 24 по умолчанию выключен; если включали — `sudo ufw allow 8814/tcp`.

## 5. Автозапуск через systemd

Чтобы не держать PuTTY открытым ради работающего сервера:

```bash
sudo tee /etc/systemd/system/philosphaira.service > /dev/null <<'EOF'
[Unit]
Description=Philosphaira
After=network.target postgresql.service

[Service]
Type=simple
User=ВАШ_ПОЛЬЗОВАТЕЛЬ
WorkingDirectory=/home/ВАШ_ПОЛЬЗОВАТЕЛЬ/philosphaira/server
EnvironmentFile=/home/ВАШ_ПОЛЬЗОВАТЕЛЬ/philos.env
ExecStart=/usr/bin/node scripts/serve.mjs
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now philosphaira
```

Управление дальше:

```bash
sudo systemctl status philosphaira
sudo systemctl restart philosphaira
journalctl -u philosphaira -f          # живой журнал
```

### Работник уведомлений — ВТОРАЯ СЛУЖБА, И ОНА НУЖНА ВСЕГДА

**Здесь прежняя редакция этой инструкции говорила неправду:** будто
`notify-worker` нужен «только если заведёте настоящую почту». Проверено по
коду (`src/notify/worker.js`): извещение в шину идёт ДО почты и НЕЗАВИСИМО
от неё. Отправитель в никуда касается только писем.

Цепочка живого отклика: коммит кладёт извещение в исходящие → **работник
публикует его в шину** → узел рассылает по сокетам → страница берёт
приращение. Нет работника — нет второго звена, и **чужая правка не доходит
до открытых страниц вовсе**.

Хуже всего, что это не видно: сервер отвечает, страница работает, правки
сохраняются. Молчит только живое обновление, и заметит это второй человек,
а не тот, кто разворачивал. Пока пользователь один — не заметит никто.

```bash
sudo tee /etc/systemd/system/philosphaira-worker.service > /dev/null <<'EOF'
[Unit]
Description=Philosphaira notify worker
After=network.target postgresql.service

[Service]
Type=simple
User=ВАШ_ПОЛЬЗОВАТЕЛЬ
WorkingDirectory=/home/ВАШ_ПОЛЬЗОВАТЕЛЬ/philosphaira/server
EnvironmentFile=/home/ВАШ_ПОЛЬЗОВАТЕЛЬ/philos.env
ExecStart=/usr/bin/node scripts/notify-worker.mjs
Restart=on-failure

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now philosphaira-worker
```

Показателя отставшего работника в продукте пока нет; если исходящие копятся,
видно запросом:

```bash
psql "$DATABASE_URL" -tAc \
  "SELECT count(*) FROM outbox WHERE delivered_at IS NULL"
```

Растущее число значит, что работник стоит или отстал.

## 6. Как войти с Windows 7

1. Откройте в браузере `http://АДРЕС:8814/`.
2. Страница, отданная сервером, несёт метку `<meta name="philos-api">` — по ней клиент и узнаёт, что сервер есть. Без метки та же страница работает как одностраничная.
3. Войдите логином и паролем первого администратора.
4. Заведите второй шаг: секрет надо перенести в приложение-аутентификатор, коды восстановления сохранить. **До этого рассмотрение коммитов, бан, смена ролей и настройки недоступны** — так задумано.

Браузер на Win7: Chrome 109 или Firefox ESR 115. Оба давно без обновлений безопасности — для хождения в свою же виртуалку это неважно, для интернета нет.

Если страница не открылась — проверьте по порядку:

```bash
curl -sI http://127.0.0.1:8814/ | head -1      # в госте: сервер жив?
ip -4 addr show                                 # адрес виртуалки тот, что вы набираете?
sudo ufw status                                 # файрвол не мешает?
```

## 7. Бессерверный режим

Главное утверждение проекта: **без сервера страница работает ровно как прежде.** Ни Node, ни PostgreSQL, ни Chrome для этого не нужны:

```bash
cd ~/philosphaira
python3 -m http.server 8711 --directory app
```

Открывается `http://АДРЕС:8711/`. Полезно как первая проверка сети — до того, как поднимать базу.

## 8. Приёмка

**Перед запуском переключите `DATABASE_URL` на испытательную базу.** Иначе рабочая будет откатана до пустого места.

```bash
cd ~/philosphaira
export CHROME=$HOME/chrome/linux-131.0.6778.204/chrome-linux64/chrome
export PUPPETEER=$PWD/node_modules/puppeteer-core
export MFA_SECRET_KEY=$(grep MFA_SECRET_KEY ~/philos.env | cut -d= -f2-)
export DATABASE_URL='postgres://philos:пароль@127.0.0.1:5432/philos_test'

bash tools/accept.sh                      # приложение и сервер разом
bash tools/accept.sh --только-приложение
bash tools/accept.sh --только-сервер
```

`PUPPETEER` скрипт подставляет и сам (строка 44), а `CHROME` — нет: умолчание в `tools/paths.mjs` указывает на машину автора. Задавайте явно, несмотря на то что `РАСПАКОВКА.md` уверяет в обратном.

Сколько ждать:

| Слой | Время |
|---|---|
| строение, карты, долг, числа документации | секунды |
| утверждения, `tip_probe`, `draft_probe` | минуты |
| шесть эталонов, сличение сторон | минуты |
| полный обход (три части на каждую из двух сторон) | около получаса |
| приёмка сервера | минуты |

Ответ — `ПРИЁМКА ЗЕЛЁНАЯ` либо `ПРИЁМКА КРАСНАЯ: N`.

Развёртывание с нуля из клона проверяет отдельная команда: `bash tools/deploy_check.sh`.

## 9. Правка исходника и пересборка

`app/` — порождаемое, правка в нём бессмысленна. Порядок из readme §5:

```bash
cd ~/philosphaira
cp -r app /tmp/app_зелёное        # СОХРАНЯТЬ ДО ПЕРВОЙ КОМАНДЫ
node tools/map_globals.mjs        # 1. пересобрать карту сущностей
node tools/remap.mjs проверить    # 2. назвать имена без дома
#                                   3. вписать их в decisions/assign_names.json
node tools/remap.mjs собрать      # 4. восемь шагов; дерево стирается ПЕРВЫМ делом
bash tools/accept.sh              # 5. приёмка
node tools/gen_spec2.mjs          # 6. спецификация
```

Копия делается до первой команды, а не после первой неудачи: `собрать` сносит дерево сразу, а останавливается на заслоне операторов позже — и восстанавливать станет нечего.

Перезапускать сервер после пересборки не нужно: `app/` отдаётся с диска при каждом обращении. Достаточно обновить страницу.

## 10. Что беречь

`server/`, `source/`, `decisions/`, `tools/` — **решения, а не производные**: пересборкой не восстанавливаются.

```bash
# база
pg_dump -Fc "$DATABASE_URL" > ~/philos-$(date +%F).dump
# восстановление
pg_restore -d "$DATABASE_URL" --clean ~/philos-2026-08-24.dump

# рукотворное (app/, node_modules/ и следы запусков не нужны)
tar -caf ~/philosphaira-$(date +%F).tar.xz \
  --exclude=node_modules --exclude=app/_ref-orig.html \
  -C ~ philosphaira
```

Отдельно и вне виртуалки — `MFA_SECRET_KEY`.

## 11. Грабли, каждая из которых уже кого-то стоила

| Признак | Причина | Лечение |
|---|---|---|
| Вошли — и сразу гость | `NODE_ENV=production` по HTTP: cookie с `Secure` не сохраняется | убрать переменную |
| Страница открылась, живого обновления нет | `WS_ORIGINS` задан и не совпадает с адресом | убрать переменную |
| Chrome не стартует, сообщение невнятное | нет системных библиотек | доставить список из 2.3 |
| `css_probe` разошёлся | другая сборка браузера | ровно 131.0.6778.204 |
| Рабочая база опустела | приёмка гонялась на боевом `DATABASE_URL` | всегда `philos_test` |
| `graph:import` отказал | граф не пуст — это защита, а не поломка | так и задумано; повтор — `ALLOW_GRAPH_REIMPORT=1` |
| `npm start` не поднял базу и не завёл людей | запуск ничего не готовит нарочно | шаги 4.1–4.3 руками |
| Логин `ИВАН` и `иван` завелись оба | база создана не в `C.UTF-8` | пересоздать базу с `--template=template0` |
