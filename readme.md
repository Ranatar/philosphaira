# ΦilosΦaira

Граф философских концепций: 453 концепции, 1624 связи, 57 философов, 22
традиции. Полотно с силовой раскладкой, 39 видов статистики, поиск путей,

## 1. Что это

Приложение о графе философских концепций: 453 концепции, 1624 связи,
57 философов, 22 традиции, 15 рубрик, 21 тип связи. Граф на полотне с силовой
раскладкой, 39 видов статистики с метриками, поиск путей, окна концепций,
философов и связей, режим правки под учётной записью, карта сходства.

Живёт в двух видах, и оба **действующие**:

| Вид | Что это | Зачем |
|---|---|---|
| `source/philosophy_graph_v3.html` | одностраничный файл, 31 404 строки | источник правды и **эталон приёмки** |
| `app/` | 115 модулей ES6 под `modules/`, база в шести JSON | то, что развивается дальше |

Второе **порождается** из первого. Это не две ветки, которые надо
синхронизировать: сборка воспроизводится в тот же байт из исходника и раскладки.

## 2. Из чего состоит сборка

Сборка — это `app/`: **115 модулей**, база в шести JSON, стили в десяти
главах. Поимённый разбор — ниже, в разделе «Что каждый файл делает»: он там
один на весь документ. Прежде такой же перечень стоял и здесь, и оба устаревали
порознь — этот обещал 80 модулей.

**Пространства имён** заменили `window[имя]`, который в модулях не работает:
`DATA` — база и производные указатели, `S` — изменяемое и отложенное,
`MET` — метрики, зовомые по имени, `VIEWS` — генераторы окон.

**Разметка несёт имя действия, а не имя функции:** `data-act-click="…"` плюс
`data-a1`. Глобальных имён у приложения нет вовсе — мост снят, `bridge.js`
удалён.

## 3. С чего начать после распаковки

```bash
npm install                       # acorn, eslint-scope, d3 — версии ЗАКРЕПЛЕНЫ
node tools/remap.mjs проверить    # целость раскладки
node tools/remap.mjs собрать      # пересборка app/ из исходника
bash tools/serve.sh                # сервер: модули по file:// не грузятся
bash tools/accept_all.sh          # полная приёмка, обе стороны
```

**Версии закреплены точно, без `^`, и это не педантизм.** Разные выпуски
`eslint-scope` по-разному разрешают ссылки: 9.1.2 и 8.4.0 дали **разные
деревья при побайтово одинаковых входных данных** — в одном `tensionIndex`
попал в пространство метрик, в другом нет. Обнаружилось это только при
проверке архива на чистом месте.

Chrome и puppeteer берутся из окружения: переменные `CHROME` и `PUPPETEER`,
по умолчанию — пути моего окружения (раздел 6). Приборы принимают ещё `BASE`
(адрес сервера), `TREE` (папка сборки) и `KEYS` (перечень обработчиков).

## 4. Цепочка сборки

```bash
node tools/split.mjs     app/ source/philosophy_graph_v3.html decisions/assign_names.json mapping/globals_map_v3.json
node tools/delegate.mjs  app/ static     # атрибуты страницы
node tools/delegate.mjs  app/ dyn        # атрибуты генераторов
node tools/rig.mjs       app/            # оснастка приборов
node tools/unbridge.mjs  app/            # снятие моста
node tools/prune_imports.mjs app/        # призрачные ввозы
node tools/prune_exports.mjs app/        # лишние вывозы
node tools/split_css.mjs app/            # стили по главам
```

Или одной командой: `node tools/remap.mjs собрать`.

**Первый шаг стирает дерево сам.** Сборка обязана начинаться с пустого места:
остаток прошлой сборки (`actions_map.json`) однажды заставил `delegate.mjs`
счесть все действия известными и молча не подключить `actions-dyn.js` —
страница поднялась с четвертью реестра при зелёных проверках строения.
Чужую папку разбивка стирать откажется: она требует признаков дерева
(`index.html`, `main.js`, `boot.js`, `modules`).

Все программы **идемпотентны**: два прогона подряд дают одинаковое дерево. Это
не пожелание, а проверка — если дерево разошлось само с собой, значит, кто-то
правил результат вместо программы.

**Раскладка задаётся именами, а не строками** (`decisions/assign_names.json`: 764 имени
и 28 операторов верхнего уровня — у оператора тоже есть дом, см. `doc/build-ops.md`).
Номера строк сдвигаются от любой вставки: по замеру тридцать чужих сущностей
молча уезжали в соседние модули. Имя, которого в раскладке нет, **останавливает
сборку** — новая сущность требует явного решения.

## 5. Как что-то менять

| Что | Где | Чем |
|---|---|---|
| поведение приложения | `source/philosophy_graph_v3.html` | правка исходника, потом пересборка |
| состав модулей | `decisions/assign_names.json` | `tools/remap.mjs` |
| разметка страницы | `source/philosophy_graph_v3.html` | там же, делегирование переведёт |
| данные | `app/data/*.json` | правка через интерфейс + «Сохранить» |

**Правка в файле `app/` бессмысленна** — следующая сборка её сотрёт.

Подробности про перестановки модулей — `doc/module-ops.md`. Кратко:

```bash
node tools/remap.mjs где <имя>                    где живёт
node tools/remap.mjs перенести <модуль> <имя...>  перенос
node tools/remap.mjs отщепить <новый> <имя...>    новый модуль
node tools/remap.mjs слить <из> <в>               слияние
node tools/remap.mjs собрать                      пересборка
```

### Когда меняется исходник

1. `node tools/map_globals.mjs <исходник> mapping/globals_map_v3.json` — пересобрать карту
2. `node tools/remap.mjs проверить` — покажет сущности без модуля
3. вписать их в `decisions/assign_names.json`
4. `node tools/remap.mjs собрать`
5. приёмка (раздел 5)
6. `node tools/gen_spec2.mjs app/ mapping/module-spec.md` — спецификация

## 6. Приёмка

Девять приборов, каждый снимает состояние **дважды** — по исходнику и по
сборке — и сравнивает хеши.

| Прибор | Что проверяет | Снимков |
|---|---|---|
| `sweep_all.mjs` | каждый обработчик разметки и каждый слушатель | 297 |
| `compare.mjs` | 39 видов статистики, окна, фильтры, пути, вход | 83 |
| `graph_probe.mjs` | наведение, клики, shift-клики под admin | 15 |
| `probe4.mjs` | перетаскивание, колесо, вывоз, печать, узкий экран | 15 |
| `probe5.mjs` | ctrl-клик, карта сходства | 15 |
| `probe6.mjs` | правка при вынесенной базе | 28 |
| `probe7.mjs` | сохранность правок | 13 |
| `probe8.mjs` | переключатель заморозки | 15 |
| `css_probe.mjs` | **вычисленные стили** каждого элемента в шести состояниях | 6 |

Плюс `check_modules.mjs` (несведённые имена, негодные ввозы, **недостижимые
модули**), `bridge_debt.py` (остатки глобального хода) и `boot_values.mjs`
(значения в сборке).

**Недостижимость — отдельный род поломки.** Файл на месте, разбор его хвалит,
страница открывается — а модуль не исполняется, потому что его никто не ввозит,
и всё, что он записывал в `MET`/`VIEWS`/реестр действий, отсутствует. Обход
ввозов от `main.js` называет такие модули поимённо; вне счёта только
`_probe-rig.js` и `dead.js`.

### Эталоны: приёмка без второй страницы

Шесть приборов из девяти имеют **замороженные эталоны** — снимки, объявленные
ожидаемыми. Тогда проверка идёт одним прогоном вместо двух и не требует
одностраничного исходника:

```bash
bash tools/accept_baseline.sh            # по эталонам, вдвое дешевле
bash tools/accept_all.sh                 # сравнение двух живых страниц
node tools/baseline.mjs состав           # что заморожено и что нет
```

**Замораживать можно лишь то, что воспроизводится.** Поэтому утверждение
эталона требует ДВУХ снимков одной стороны и отказывается, если они
разошлись; отказывается и когда в снимке есть хоть одна ошибка страницы.
Заслон не выдуман: `probe4` дал расхождение снимка «узкий экран» между двумя
прогонами исходника, а выбранный узел оказался разным — `phronesis` против
`ideal_state`. Вместе с ним не замораживаются `graph_probe` и `probe5`: все
трое считают от раскладки, которая меряет шаги по реальному времени.

**Но двух прогонов мало, если величина двумодальна.** Проверено опытом на
обходе: прогоны А и Б совпали полностью, утверждение прошло — а третий прогон
разошёлся с новым эталоном на 38 снимках и сошёлся с прежним. Два попадания в
одну моду неотличимы от воспроизводимости. Поэтому перед заморозкой — **три
прогона**, и лучше не подряд.

**Но три нужны не всегда.** Двумодальность жила в счёте метрик: величины,
считаемые с задержкой, попадают в снимок по-разному. Отсюда измеримый признак,
а не чутьё: правка задевает `similarityData`, метрики или укладку — три прогона;
правка касается разметки, стилей, прозрачности — довольно одного, а
освободившееся время честнее потратить на сличение сторон.

**Повтор не отвечает и на вопрос «вылечено ли».** Прошлый разбор объявил
двумодальность обхода снятой на основании четырёх совпавших прогонов — а звено,
которое якобы чинилось, оказалось непричастным: возврат режима значений работал
исправно, но легенда от режима не зависит вовсе. Причиной был глухой срок
ожидания вида, и нашёлся он прямым замером за минуту. Повтор говорит
«устойчиво», сличение сторон — «не врёт», а «вылечено» говорит только замер
самой причины.

**И повторный прогон отвечает не на тот вопрос.** Он говорит, устойчив ли
прибор; врёт ли он — говорит только сличение сторон. Возврат состояния,
написанный через имена (`__app.S.metricValueMode`), стабилизировал сборку и
молча не работал на исходнике, где это `let` и в `window` оно не попадает:
три совпавших прогона выглядели победой, а стороны разошлись на 43 снимках.
Отсюда: **о состоянии страницы прибор спрашивает разметку, а не имена** —
имена у сторон устроены по-разному, разметка одна. И сличение сторон делается
раньше проверки на устойчивость.

**Чего эталон не делает.** Он отвечает «стало ли иначе, чем было», а не
«правильно ли». Снятый с испорченной стороны, он закрепит поломку как норму —
таких случаев уже три: разбор собственного `onclick` в подсветке вкладок,
пустая проверка подсветки узла, пропавшая кнопка «Нормировать». И всякая
НАМЕРЕННАЯ правка рушит эталоны разом, без различения умысла и случайности.
Поэтому эталоны — только первый слой.

### Второй слой: утверждения о должном

`tools/assert_probe.mjs` — **137 утверждений**, записанных числами и условиями,
а не хешами. Ему не нужны ни исходник, ни эталон: он гоняется по одной сборке
и говорит, что ДОЛЖНО быть верно.

Проверяются: база и производные указатели (453 концепции, 1624 связи, и
указатели совпадают с базой по числу); все имена действий известны реестру,
встроенных обработчиков ноль, десять таблиц стилей; панели отрисованы по
данным; **каждая из 39 вкладок даёт непустое содержимое и ровно одну
подсветку**; окна называют то, что открыли; поиск не тащит постороннего;
без входа кнопки правки нет, под admin есть; правка доходит до базы и до узла
графа; сериализатор отдаёт шесть наборов; контраст подписей не ниже 4,5;
ошибок страницы нет.

Второй слой окупился сразу: он нашёл дефект, которого не видел ни один из
восьми прежних приборов, — список найденного в поиске легенды остался со
светлой кожи (белый прямоугольник поверх тёмной панели, контраст имени
философа 3,48). Сравнение двух страниц молчало, потому что **неверны были
обе**.

### Единый поиск концепций

Пять мест искали концепции по-своему. Сведены к одному устройству по образцу
поиска в окне просмотра связи: список выпадает ВЕСЬ по фокусу, в
хронологическом порядке философов и по алфавиту внутри философа; строка —
кружок цвета философа, название и под ним имя философа.

Отбор считает `отобратьКонцепции`, внутренности строки рисует
`внутренностиСтроки`, облик задан классом `.concept-row` один раз.

**Обработчик каждый вызывающий пишет БУКВАЛЬНО**, подставляя только доводы.
Подставишь весь вызов целиком (`onclick="${действие}"`) — делегирование
увидит один довод и не поймёт, что звать: строки списка станут мёртвыми, а
поиск пути с пустым выбором уведёт вкладку в петлю. Ровно на этом уже
спотыкался `modalActions`.

**Урок о проверке.** Первая проверка меню меряла РАЗМЕТКУ — сколько строк,
есть ли кружок, есть ли имя философа. Всё сходилось, а меню были мертвы.
Проверять надо НАЖАТИЕ: щелчок по строке в списке пути заполняет поле,
щелчок в легенде закрывает список.

### Третий слой: разбор при расхождении

`tools/snapshot.mjs` — общий снимок для всех приборов: не один хеш на всё, а
**ещё и по кускам** (32 на снимок). При расхождении прибор говорит не
«разошлось», а «разошлось в куске 17 из 32 (знаки 3200–3400 из 6400)» либо,
для снимков обхода, «поле 2 из 5: было `123:45`, стало `999:45`». Короткие
значения хранятся целиком.

Раньше каждый такой разбор требовал отдельной программы и целого захода — за
работу это случалось раз шесть.

```bash
# эталон кладётся в дерево, чтобы обе стороны шли с одного сервера
python3 -c "s=open('source/philosophy_graph_v3.html').read().replace(
  'https://cdnjs.cloudflare.com/ajax/libs/d3/7.8.5/d3.min.js','./vendor/d3.min.js');
  open('app/_ref-orig.html','w').write(s)"
cd app && python3 -m http.server 8711 &

node tools/sweep_all.mjs run _ref-orig.html o1.json 1   # части 1, 2, 3
node tools/sweep_all.mjs run index.html     m1.json 1
node tools/sweep_all.mjs merge свод_и.json - o1.json o2.json o3.json
node tools/sweep_all.mjs diff свод_и.json свод_м.json
```

Модули по `file://` не грузятся — **сервер обязателен**.

## 7. Как это делалось в моём окружении

Практические частности, без которых половина работы уходит в песок.

**Chrome и puppeteer лежат не там, где ожидаешь.** Chrome 131 —
`~/.cache/puppeteer/chrome/linux-131.0.6778.204/chrome-linux64/chrome`;
puppeteer 23.11.1 — в недрах `mermaid-cli`:
`~/.npm-global/lib/node_modules/@mermaid-js/mermaid-cli/node_modules/puppeteer`.
Запуск: `headless: 'new'`, ключи `--no-sandbox --disable-dev-shm-usage
--disable-gpu`.

**Памяти четыре гигабайта, и этого не хватает.** Вкладка с 400 снимками
разметки падает на двадцать девятом виде. Лечение: дробить прогон на части,
**каждую отдельным запуском процесса**, и сводить снимки потом (`run` → `merge`
→ `diff`). Две страницы в одном браузере тоже не живут — по одной на запуск.

**Версия разбора областей видимости влияет на итог.** Проверено на архиве:
`eslint-scope` 9.1.2 и 8.4.0 при одних и тех же входных данных дают разные
деревья. Поэтому версии в `package.json` закреплены точно.

**Разбор кода — настоящим разбором, не выражениями.** `acorn` плюс
`eslint-scope`: затенённые местные имена иначе путаются с глобальными. Карта
сущностей (`map_globals.mjs`) построена на этом и потому не врёт.

**Раскладка графа не повторяется от загрузки к загрузке.** Сила укладки считает
шаги по реальному времени; у двух прогонов **одной и той же** страницы разные
координаты — вплоть до того, что самый связный узел выпадает разный. Отсюда:
из вывезенного SVG перед сверкой вычёркиваются все числа; перетаскивание
сверяется допуском, а не точным сдвигом.

**Перед кликом по графу раскладку надо остановить.** Ждать `alpha <= 0.001`,
звать `freezeSimulation` — и **перед каждым действием заново**: закрытие окна
зовёт разморозку, и узел уезжает из-под курсора между шагами.

**Синтетическая мышь ведёт себя не как живая.** `clickCount: 2` шлёт одно
событие с `detail: 2`, а приложение считает клики само и ждёт два в пределах
300 мс. Выход за границу элемента браузер вычисляет на **следующем** входном
событии: уведёшь курсор одним прыжком — `mouseleave` придёт с запозданием на
шаг, и покажется, будто подсказка не гаснет.

**Точку на графе спрашивать у приложения, а не вычислять.** Узел может лежать
за краем окна или под панелью. Требовать: `elementFromPoint` даёт именно
полотно, `pickNode` подтверждает попадание.

## 8. Чему научила приёмка

Это не отступление: почти каждое правило куплено потерянным заходом.

**Прежде чем звать расхождение дефектом, прогони одну и ту же сторону дважды.**
Дважды «дефект» оказывался шумом прибора — и один раз это заметил не я, а вы.

**Прибор не должен оставлять следов в том, что измеряет.** Обход помечал
элементы своим признаком, признак попадал в хеш — 54 ложных расхождения.

**Не сравнивай длину разметки.** Она меняется от одной формы записи
обработчика: `onclick="…"` против `data-act-click="…"` плюс `data-a1`.

**Не опирайся на то, что случайно оказалось в `window`.** В обычном сценарии
туда попадают объявления функций, но **не** `let` и `const`; в сборке — только
то, что выставлено намеренно. Проверка подсветки узла годами ничего не
измеряла именно из-за этого.

**Сравнивай только снимки одной версии прибора.** Четыре раза ложная тревога
приходила оттуда, что одна сторона снята старой версией.

**Проверяй не текст правки, а результат.** Замена в программе может не
совпасть по экранированию и молча ничего не сделать — я так потерял два захода.

**Новый прибор проверяй подложенной поломкой, а не тем, что он зелёный.**
Проверка свежести карт сравнивала через `JSON.stringify` со списком ключей
вторым доводом — а там он работает отбором, и всё вложенное выпадало из
сравнения. На нарочно испорченной карте прибор говорил «свежая».

### Расхождение бывает двух природ, и различать их — работа человека

Одно следует из замысла: кнопка стала называться иначе — эталон переутвердить.
Другое означает изъян. Приборы сообщают об обоих одинаково громко.

**Первый вопрос при любом расхождении — прогнать одну сторону дважды.** Если
она расходится сама с собой, виноват прибор, и в приложении искать нечего.
За последние заходы так вскрылись четыре неустойчивости подряд.

**Перестановка модулей, сломавшая снимки, — тревога. Правка разметки,
сломавшая снимки, — следствие замысла.** Во время развязки слоёв эталоны не
дрогнули ни разу: устройство менялось, поведение нет. Когда менялась разметка,
их приходилось переутверждать каждый раз, и это правильно.

### Прибор спрашивает о неизменном, а не о том, что зависит от скорости

Три неустойчивости подряд имели один корень: вопрос был про то, что гуляет от
прогона к прогону.

| Что спрашивал прибор | Почему гуляло | Как спросили заново |
|---|---|---|
| ключ снимка со ссылкой на имя вида статистики | обработчик срабатывает в том виде, где попался первым, а метрика считается порциями | ключ по области, без имени вида |
| содержимое вида статистики целиком | длина скакала между 1359 и 22 261 знаком — успела ли посчитаться метрика | облик: число кнопок, полей, заголовков, строк |
| «едет ли раскладка», «есть ли ей куда ехать» | время до остановки скачет от 1 до 22 секунд | «не заморожена ли раскладка» |

**Лечение всякий раз одно: не менять состояние ради удобства прибора, а
переформулировать вопрос.** Попытка пойти обратным путём — досчитывать метрику
перед снимком — роняла вкладку и была откачена. Это верный признак: если ради
измерения приходится добавлять тяжёлую работу, приём неверен по существу.

### Прибор обязан возвращать состояние, а не только не оставлять меток

Правило «не оставлять следов» шире, чем казалось, и всплывало трижды:

- визуализация метрики меняет радиусы и раздел легенды — обход снимает её
  после снимка;
- она же **закрывает окно статистики** — обход запоминает его состояние до
  действия и возвращает после (покрытие в видах при этом выросло с 22
  обработчиков до 27: окно перестало закрываться посреди обхода);
- один блок утверждений снимал галочку хронологии и не возвращал её —
  проверки идут по одной странице и обязаны оставлять её такой, какой взяли.

### Инструмент, который не может сказать, чего ему не хватает

Дважды причина пряталась за поломкой самого инструмента: разбивка при имени
без модуля звала несуществующую функцию и вместо «нет модуля для такого-то»
выдавала «lineIn is not defined»; сервер приёмки менял рабочую папку, получив
относительный путь, и молча отвечал «000» на любой запрос.

**Молчаливый отказ дороже громкого.** Оба лечатся одинаково: заставить
программу назвать, чего ей не хватает.

### Приборы находят больше, чем просят

Обход сам обнаруживает каждое новое нажимаемое место — за последние заходы
атрибутов стало 224 против 196, различных обработчиков 135 против 117. А
утверждения дважды нашли то, о чём никто не спрашивал: контраст стрелок пути
2,26 и белый список поиска поверх тёмной панели.

Подробности каждого случая — в `doc/history.md`; здесь только правила.

## 9. Стили

Таблица стилей — 117 614 знаков, 4438 строк, 654 правила — разнесена по десяти
главам: основа, легенда, общая кожа окон, окно философа, поиск пути,
хронология, статистика, итоги, напряжение, формы правки. Карту строит
`tools/css_map.mjs`, режет `tools/split_css.mjs`.

**Порядок подключения значим** — семь селекторов встречаются в двух главах, и
при равной весомости побеждает последний. Поэтому главы режутся по границам,
а не по темам вразброс: склейка глав по порядку обязана совпадать с исходным
блоком знак в знак, и разрезатель это проверяет сам.

Проверка стилей дешёвая, но нужна, и вот почему. Первый разрез сходился по
склейке знак в знак — и всё же был испорчен: якорь главы указывал в СЕРЕДИНУ
пояснения, файл открывался обрывком `*/`, браузер отбрасывал правила пачками,
198 элементов из 3780 остались без оформления. Механическая проверка такого
не ловит в принципе; поймала сверка **вычисленных** стилей. Отсюда второй
заслон: глава не может начинаться внутри пояснения.

## 10. Что осталось

- **Долгов переноса больше нет.** Счётчик показывает ноль по всем четырём
  строкам: атрибутов `on*` 0 из 224, имён в мосте 0, записей в `window` 0,
  обращений `window[выражение]` 0.
- **Мёртвый модуль** `dead.js` — семь сущностей, к которым не обращается
  никто. Решение (оставить, вернуть в дело или выбросить) не принято. Полной
  изоляции у модуля нет: `metrics/cache.js` ввозит `invalidateTensionScales`,
  потому что общий сброс кешей его перечисляет.
- **Контраст глифа** `.connection-arrow.cw-2` (1,88…4,19): цвет берётся от
  ТИПА СВЯЗИ, то есть из данных, и переменной темы не решается. Нужен другой
  ход — обводка или тень под глифом. Это правка облика, а не долг переноса.
- **Сохранность правок есть, но местная.** Выгрузка шести JSON и запись в
  папку через File System Access. Настоящее хранилище — за сервером: там же
  проверка прав (сейчас `canEdit()` переключается из консоли, и в коде так и
  написано), разрешение столкновений, история правок.
- **Постоянные модули из спецификации, до которых не дошли:** `core/events.js`
  (шина вместо прямых обращений снизу вверх), `metrics/registry.js` (вместо
  перечня из сорока сбрасывателей). Сейчас их роль играют прямые ввозы; это
  работает, но ацикличность держится на том, что тела модулей — почти одни
  объявления.
- **Старые незакрытые контрасты:** `.connection-arrow.cw-2`, `.similar-col-hint`.
- **Развилка на будущее.** Пока обе стороны действующие, приёмка сравнивает
  сборку с исходником. Когда одностраничную версию отпустят, сравнивать станет
  не с чем — и приборы должны будут проверять не «совпадает с исходником», а
  «делает то, что должно», то есть обзавестись собственными ожиданиями. Работа
  отдельная, начинать её лучше заранее.

## 11. Слои и развязка

Порядок слоёв объявлен в `tools/layers.mjs` — это единственное, что задано
руками; всё прочее считается. Прибор показывает рёбра, идущие СНИЗУ ВВЕРХ:
их было **35 (45 имён)**, стало **0**.

```
core/ util/ (0) → data/ state.js (1) → metrics/ (2) →
render/ graph/ filters/ (3) → widgets/ paths/ (4) →
stats/ modal/ (5) → ui/ (6) → boot main (9)
```

**Три приёма развязки, в порядке предпочтения:**

1. **Перенос вниз** — если сущность оказалась общей услугой не на своём
   этаже (сообщения пользователю, поиск концепций, состояние выбора пути).
2. **Перенос по смыслу** — если она просто лежала не там: работа с графом
   уехала из слоя данных в `graph/`, выбор на полотне — туда же.
3. **Разворот зависимости через шину** (`core/events.js`) — когда перенос не
   помог бы: фильтры не обязаны знать о легенде, щелчок по полотну — об
   окнах. Список событий объявлен; известить о неизвестном — **ошибка, а не
   тишина**. Подписки ставит СБОРКА: только ей позволено знать обо всех разом.

**Отдельный слой `widgets/`** появился потому, что `ui/` смешивал две разные
вещи: сборщиков экранов (легенда) и виджеты, которыми экраны ПОЛЬЗУЮТСЯ
(выпадающий список концепций). Экран, зовущий виджет, — это вниз, а не вверх.

**Призрачные ввозы.** Разбивка ищет нужные ввозы по тексту модуля и находит
имена внутри шаблонных строк разметки. Пока обработчики были встроены, ввоз
был настоящим; после делегирования имя осталось только в строке ввоза.
Таких набралось **49 в 15 модулях** — и они давали ЛОЖНОЕ СЦЕПЛЕНИЕ: карта
считала их связями, и один из кругов держался ровно на них.
`tools/prune_imports.mjs` убирает их; шаг вписан в цепочку сборки.

**Кругов не осталось.** Было один на 43 модуля. Последние два разобраны так:

- **Цикл кадров развязан назначением.** Было замкнуто накрепко: цикл ввозил
  отрисовку, отрисовка ввозила цикл. Теперь `render/loop.js` НЕ ЗНАЕТ, что
  рисовать — рисовальщика ему назначает сборка, а если тот не назначен, цикл
  ругается вслух, а не рисует пустоту.
- **Метрики расщеплены по существу.** `metrics/scope.js` делал две разные
  вещи: отдавал чистые выборки (какие узлы и связи в области счёта, какие
  признаки включены) и распоряжался сбросом кешей. Первое уехало в
  `metrics/scope-core.js`, второе осталось.
- **Мёртвый модуль выведен из графа**: кеш напряжения и его сбрасыватель
  переехали к прочим кешам метрик, и `dead.js` перестал быть чьей-либо
  зависимостью. Ничего не выброшено, поведение не тронуто — просто склад
  больше не держит дом.

**Призрачные ввозы бывают затенёнными.** `render/geometry.js` ввозил `draw` у
отрисовщика, а внутри функции объявлял СВОЙ `const draw`: по тексту имя есть,
по делу ввоз мёртв. Уборщик, искавший по тексту, такое пропускал — переписан
на разбор областей видимости, считаются ССЫЛКИ на ввезённое имя. Так нашлись
ещё одиннадцать, все затенённые.

## 12. Раскладка и карты: решения против производного

Это различение важнее самих карт, и путать их легко.

**РЕШЕНИЯ — то, что принимает человек и что надо беречь.** Их всего два файла:

| Файл | Что в нём |
|---|---|
| `decisions/assign_names.json` | раскладка: 764 имени и 28 операторов → модуль. Перенос сущности — это правка ЗДЕСЬ, а не в дереве |
| `decisions/layers.json` | порядок этажей: ввозить можно вниз и вбок, не вверх |
| `tools/layers.mjs` (список `СЛОИ`) | объявленный порядок слоёв — единственное, что задано руками при развязке |

Потерять их — значит потерять работу: восстановить придётся по памяти. Всё
остальное восстанавливается за минуту.

**ПРОИЗВОДНОЕ — то, что пересчитывается, и потому не жалко.** Дерево `app/`
целиком, и три карты:

| Карта | По чему | Что отвечает |
|---|---|---|
| `globals_map_v3` | по одностраничному исходнику | сущности в одной области видимости, кто к кому обращается, вызовы из разметки. **Нужна разбивке** |
| `css_map` | по блоку `<style>` исходника | главы, правила, межглавные повторы селекторов |
| `map_tree` | **по собранному дереву** | кто у кого что ввозит, вывоз впустую, мёртвые сущности, круги, плотность обращений к `DATA`/`S`/`MET`/`VIEWS` |

Первые две описывают ИСТОЧНИК, третья — то, ЧТО РАБОТАЕТ. Когда одностраничную
версию отпустят, первые две исчезнут вместе с ней, третья останется.

**Что означает «все карты свежие».** Не «их не пришлось трогать», а «ни одна не
отстала от того, что описывает». Разница существенная: за одну только развязку
слоёв переехало **38 имён**, прибавилось **6** (шина и цикл кадров), модулей
стало 92 вместо 87 — и все карты при этом пересобирались по ходу, иначе сборка
просто не пошла бы. Проверку делает `tools/maps_fresh.mjs`: пересобирает каждую
заново и сличает, не считая отметки времени и записанного пути.

**Устаревают они по-разному, и это важнее, чем кажется.** `decisions/assign_names.json`
устареть незаметно НЕ МОЖЕТ: новое имя останавливает сборку с перечнем.
`globals_map_v3` устареет тише: сборка соберётся, но метрики по имени,
обработчики разметки и ячейки общего состояния окажутся посчитаны по
вчерашнему коду. А `mapping/css_map.json` не читает НИКТО (главы разрезатель берёт из
`css_map.mjs`) — эта устареет совсем молча, и это худший случай из трёх.

Поэтому есть `tools/maps_fresh.mjs`: пересобирает каждую карту во временное
место и сличает, не считая отметки времени и записанного пути. Он вписан в обе
приёмки.

**Что показала третья.** Круговая группа из 43 модулей — половина дерева
ввозит друг друга. Это не поломка (тела модулей почти одни объявления, взаимный
ввоз безопасен, приёмка зелёная), но знак, что граница между областями
проведена не по живому. Плотнее всего ввозят из `metrics/init.js`,
`stats/results.js`, `stats/modal.js`, `modal/core.js`.

**Вывоз впустую и мёртвая сущность — разные вещи.** Разбивка вывозит все
собственные имена подряд, поэтому «вывезено и никем не ввозится» встречается
Лишних вывозов теперь **ноль**: их снимает `prune_exports.mjs`, восьмой шаг
сборки. Прежде их было 203 — разбивка вывозит все собственные имена подряд, и
список вывоза переставал что-либо сообщать: обещания наружу было не отличить от
внутренней кухни.

**Что чистка не трогает.** Имя, ввезённое хоть одним модулем, `main.js` или
оснасткой `_probe-rig.js` (таких два — они и стоят в сводке отдельной мерой
«нужны приборам»). Весь `modules/dead.js`: там вывоз есть **опись склада**.
И — самое важное — **мёртвое имя вывоза не лишается**: сняв вывоз с того, что не
работает и внутри своего модуля, мы спрятали бы улику от карты, потому что
`map_tree` смотрит именно список вывоза. Проверено на себе: в первой попытке
`searchNodes` и `graphSelectionContext` исчезли из виду, и «мёртвых сущностей»
стало ноль. Чистка убирает шум, а не улики.

**Разбор прежних 203** (сделан после вопроса «неужели все они не нужны»): 194
внутри своего модуля работали и вывозились впустую — их и сняли; два нужны
приборам; две — мёртвые, оставлены на виду.

**Тот же разбор вскрыл перекос в счётчике.** `map_tree.mjs` считал обращения
обходом всего разбора, а в `export { a, b }` каждое имя даёт **два**
узла-идентификатора — `local` и `exported`. Счёт выходил завышенным ровно на
два, и всякое имя, не используемое внутри своего модуля ни разу, получало
«внутри = 2» и попадало в лишние вывозы вместо мёртвых сущностей. Вывоз
объявлением (`export function f`) перекоса не давал — потому пряталось только
перечислительное.

Показатель «мёртвых сущностей 0» держался этим перекосом. После правки их
оказалось шесть: четыре законно лежат в `modules/dead.js`, а две — находки:

| Имя | Где | Что это |
|---|---|---|
| `searchNodes` | было `core/search.js` | объявлено и не вызывается нигде, включая **исходник** |
| `graphSelectionContext` | было `state/edit.js` | тень: живое состояние — в `S`, эта копия никогда не обновлялась |

Обе **перенесены в `modules/dead.js`**: на складе шесть, мёртвых сущностей
ноль. Показатель, который никогда не ноль, не стерегут — глаз привыкает к
двойке и перестаёт отличать её от тройки.

Склад теперь считается отдельной мерой (`сложеноВСклад`): `dead.js` мёртв по
замыслу, и пока он шёл общим счётом, показатель нельзя было держать в нуле —
а значит и следить за ним. Проверено подложенным именем: неупотребимая
функция в `core/search.js` тут же попала в перечень находок. Имён, не помянутых нигде —
ни снаружи, ни внутри своего модуля, — **ноль**. Одно (`actionNames`) держится
только приборами приёмки и считается отдельно.

## 14. Что запускать при каждом изменении

Порядок не произволен: каждый шаг опирается на итог предыдущего.

```bash
# 1. Правка вносится В ИСХОДНИК source/philosophy_graph_v3.html — не в app/.
#    Правка в дереве бессмысленна: следующая сборка её сотрёт.

# 2. Карта исходника — первым делом: по ней считается раскладка.
node tools/map_globals.mjs source/philosophy_graph_v3.html mapping/globals_map_v3.json
node tools/css_map.mjs source/philosophy_graph_v3.html mapping/css_map.json     # если трогали стили

# 3. Новые имена требуют ЯВНОГО решения — сборка иначе встанет с перечнем.
node tools/remap.mjs проверить
#    вписать новые имена в decisions/assign_names.json, затем:
node tools/remap.mjs собрать        # восемь шагов + проверка имён

# 4. Устройство: слои и круги.
node tools/layers.mjs ввозы         # должно быть 0
node tools/map_tree.mjs app mapping/map_tree.json && python3 tools/map_tree_to_md.py mapping/map_tree.json mapping/map_tree.md
python3 tools/bridge_debt.py app    # долг должен быть 0
node tools/boot_values.mjs app      # значений в сборке должно быть 0

# 5. Приёмка. Эталон кладётся в дерево, поднимается сервер.
python3 tools/make_ref.py source/philosophy_graph_v3.html app
bash tools/serve.sh
node tools/assert_probe.mjs index.html      # 137 утверждений — САМОЕ ВАЖНОЕ
bash tools/accept_baseline.sh               # по эталонам, один прогон
#    либо, если сомневаетесь в самих эталонах:
bash tools/accept_all.sh                    # сравнение двух живых страниц

# 6. Если снимки разошлись — РЕШИТЬ, что это.
#    Перестановка модулей сломала снимки → ТРЕВОГА: устройство меняли, а
#    поведение поехало. Правка разметки сломала → ожидаемо, переутвердить:
node tools/baseline.mjs утвердить <прибор> <снимок1> <снимок2>   # ДВА прогона ОДНОЙ стороны

# 7. Карты и документы.
node tools/gen_spec2.mjs app mapping/module-spec.md
python3 tools/map_to_md.py mapping/globals_map_v3.json mapping/globals_map_v3.md
node tools/maps_fresh.mjs           # все карты свежие?

# 8. Воспроизводимость и упаковка.
#    Пересобрать в чистое место и сличить: цепочка обязана давать тот же байт.
```

**Три правила, за которые заплачено заходами.** Прежде чем звать расхождение
дефектом — прогнать ОДНУ И ТУ ЖЕ сторону дважды. Новый прибор проверять
ПОДЛОЖЕННОЙ ПОЛОМКОЙ, а не тем, что он зелёный. Проверять не текст правки, а
результат — перечитать изменённое место.

## 16. Что приходит ввозом, а что — событием

Устройство запуска держится на одном различии: **ввоз даёт обещание порядка,
всё прочее — нет.** Ни `DATA`, ни `S`, ни глобальная переменная не говорят
ничего о том, вычислено ли уже то, к чему обращаешься.

Поэтому ввозом приходит всё, что может:

- **база** — `core/ns.js` статически ввозит шесть `.json`
  (`import … with { type: 'json' }`) и собирает `DATA` до исполнения любого
  тела. `loadData()` осталась именем и возвращает готовый `DATA`;
  асинхронности в запуске нет;
- **`d3`** — `vendor/d3.js` есть обёртка над поставляемой UMD-сборкой
  (`import './d3.min.js'; export default globalThis.d3;`), и разбивка
  добавляет `import d3` в каждый модуль, где имя упомянуто; классического
  `<script src>` в разметке нет;
- **производные указатели** — `buildIndexes()` вызывается в конце тела
  `core/graph-index.js`. Модулю, читающему `DATA.<указатель>` при вычислении
  своего тела, приписывается `import './core/graph-index.js';` **без имён** —
  ввоз ради порядка;
- **имена пространств `MET` и `VIEWS`** — заполняются телами своих модулей,
  и ссылающийся на них получает такой же ввоз ради порядка.

**Что этим НЕ затронуто:** правка в приложении никогда не перечитывала базу —
она меняет `DATA` в памяти и зовёт `afterDataChange`. Обновление вида без
перезагрузки работает как прежде. Пропала лишь возможность перечитать `.json`
с диска в ходе работы, а ею никто не пользовался.

**Оговорки:** `with { type: 'json' }` — вещь свежая, ограничение по браузерам;
по `file://` не работает, но модули там и так не грузятся.

## 17. Признак `boot`: сборка соединяет, а не вычисляет

**В теле `boot()` не должно оставаться ни значений, ни дел.** Значение уезжает
в модуль-владелец; дело — тоже, потому что у оператора верхнего уровня есть
дом ровно так же, как у имени (`decisions/assign_names.json`, раздел
`операторы`; ключ и порядок — в `doc/build-ops.md`).

В сборке остаётся только связывание: `await loadData()`, вызовы установок,
подписки на шину, `onReady`/`onLoad` и несколько записей о ходе запуска. Ныне
это 100 строк против 1483 в начале разбора.

Значение уезжает домой, если всё, на что оно ссылается, **готово к моменту
вычисления тела**: встроенное, окружение (разметка есть — скрипт модульный),
`d3`, сырая база, производные указатели, обычные сущности чужих модулей, имена
пространств — и **другие разрешимые ячейки**, если поставить ввоз к их модулю.
Последнее считается до неподвижной точки: `spacingX = viewWidth / (cols + 1)`
разрешимо ровно постольку, поскольку разрешимо `viewWidth`.

**Признак проверяется прибором, а не глазом:**

```
node tools/boot_values.mjs
  boot(): кусков 69, строк 100
  значений в сборке: 0 — признак соблюдён
```

Прибор считает присваивания самим ячейкам и отличает их от обращений к
готовому. Место в приёмке — с прочими приборами строения, до запуска страницы.

**Чего он НЕ ловит и что стоит помнить.** Он видит значения, но не видит дел:
оператор, знающий об одном предмете (`getElementById('chronologyModeSelect')`),
для него неотличим от связывания. Такие места ищутся глазами по составу
`boot.js` — и, найдясь, получают дом в разделе `операторы`.


## 18. Исключения в счёте слоёв

`layers.mjs` не считает нарушением ввоз из:

- **`data/*.json`** — у файла данных нет своих ввозов, он ни от чего не
  зависит и лежит ниже всех, где бы ни лежала его папка;
- **`vendor/*`** — обёртка над поставляемой сборкой, своих зависимостей не
  имеет;
- **`dead.js`** — не часть устройства, а склад.

`check_modules` по той же причине проверяет `vendor/*` и `*.json` на наличие
файла, а не на вывозы: разбирать там нечего.
