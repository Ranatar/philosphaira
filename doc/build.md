# Разбивка `philosophy_graph.html` на модули — сборка

Дерево получено программой `split.mjs` из исходного одностраничного файла
по спецификации `module-spec.md`. Ручных правок в дереве нет: всякая правка
вносится в программу и сборка пересобирается заново.

## Как запустить

Модули требуют http — по `file://` браузер их не отдаст.

```bash
python3 tools/serve.py 8000 app     # многопоточный; `python3 -m http.server` не годится
# затем http://127.0.0.1:8000/index.html
```

Однопоточный сервер отдаёт файлы по одному, а страница тянет больше сотни
запросов: ожидание «сеть утихла» перестаёт наступать, и приборы падают по
времени. Ещё: `tools/serve.sh` держит переменную с кириллическим именем —
bash её не примет, сервер молча не поднимется. Звать `serve.py` напрямую.

## Что где

Полный перечень — в `readme.md`, раздел «Что каждый файл делает»: там разобраны
и корень проекта, и `tools/`, и корень `app/`. **Держится он в одном месте
намеренно** — прежде тот же перечень стоял ещё и здесь, и здешний устарел
незаметно: обещал мост, которого уже нет, четыре слушателя вместо шести, 80
модулей вместо 103 и 2,7 МБ данных вместо 1,8.

Самое короткое, что нужно знать сразу:

| Путь | Что |
|---|---|
| `index.html` | разметка без скрипта; подключает `./main.js` модулем |
| `main.js` | ввозит все модули поимённо, ставит делегирование, запускает |
| `boot.js` | СБОРКА: слушатели, подписки шины, первые вызовы. Значений в нём нет — см. `readme.md`, «Признак boot» |
| `vendor/d3.js` | обёртка над UMD-сборкой d3: `import './d3.min.js'; export default globalThis.d3` |
| `core/ns.js` | четыре пространства имён: `DATA`, `S`, `MET`, `VIEWS` |
| `data/*.json` | шесть наборов базы |
| `_probe-rig.js` | точки входа для приборов приёмки; **не часть приложения** |
| `actions_map.json` | имя действия → исходный текст обработчика (для приёмки) |

## Пространства имён

`DATA` — данные и производные указатели. **База приходит ввозом**: `core/ns.js`
статически ввозит шесть `.json` (`import … with { type: 'json' }`), поэтому
`DATA` полон до исполнения любого тела. Производные указатели строит
`buildIndexes()` в конце тела `core/graph-index.js`.
`S` — изменяемое состояние (63 поля): то, что меняется из чужого модуля.

**Почему `map_tree.mjs` показывает у `S` 66 полей, а не 62.** Карта дерева
считает не объявленное, а **упомянутое** — всякое `S.что-то`, встреченное в
коде. Разница объясняется целиком и дефекта не содержит:

- четыре поля упоминает только оснастка `_probe-rig.js`, и упоминает
  **с запасным ходом**: `S.selectedNodes !== undefined ? S.selectedNodes :`
  и дальше ввоз из `state/render.js`. Приборам нужно одно имя для обеих
  сторон, а живут эти величины в вывозах модулей, не в `S`;
- `S.graphSelectionContext` — настоящее поле состояния (пишется в
  `graph/graph-selection.js`, читается в пяти модулях), но в
  `namespaces.json` его нет: в исходнике это `window.graphSelectionContext`,
  а присваивание к `window` на верхнем уровне разбор считает объявлением и
  выдаёт ему дом. Дом достался `state/edit.js`, где стоит `let
  graphSelectionContext` с вывозом, **которого никто не ввозит**: это один из
  мёртвых сущностей: `prune_exports.mjs` вывоз с него намеренно не снимает,
  чтобы улика оставалась видна карте. Живое состояние — в `S`, копия в
  `state/edit.js` мертва и никогда не обновляется.

Есть и ловушка для всякого счёта по образцу: в `metrics/network.js` объявлен
**местный** `const S = []` — стек обхода. Его `S.push`, `S.pop` и `S.length` к
пространству состояния отношения не имеют, но попадают в любой подсчёт
`S\.имя` регулярным выражением. Считать состав `S` следует по
`namespaces.json`, а не поиском по тексту.
Начальные значения живут в модулях-владельцах, а не в сборке.
`MET` — 33 метрики, к которым обращаются по имени.
`VIEWS` — шесть генераторов окон, к которым обращаются по имени.

Три последних заменили `window[имя]`, который в модулях не работает вовсе.

`sweep_all.mjs` — полный обход. Приложение проводится по всем состояниям,
где вообще появляется разметка (главная страница, 39 видов статистики, окна

различный обработчик. Различие считается по тексту атрибута с вычеркнутыми
подстановками: 224 атрибута дают 135 различных обработчиков, поэтому
тридцать одинаковых карточек не гоняются тридцать раз, а покрытие полное.
Два необойдённых — подставляемое имя функции (`${saveFn}()` в
`modalActions`); все шесть развёрнутых видов сработали на обеих сторонах.
Отдельно проходятся слушатели из кода: Esc при статистике и при окне, клик
по подложке, клик мимо выпадающего списка, переключатель и режим хронологии,
изменение размера окна, выход из учётной записи.

Четыре условия, без которых обход неполон:

1. **Один проход мало**: элементы стоят в порядке разметки, кнопка закрытия
   попадается раньше прочих — окно захлопывается, и хвост списка исчезает.
   Область открывается заново, пока новых обработчиков не остаётся.
2. **Состояние надо возвращать**: обход главной страницы жмёт «Сбросить» и
   меняет режимы, после чего сравнение философов не строится вовсе.
3. **Пару связанных концепций мало взять из подписи — её надо ПРОВЕРИТЬ**
   через `findConnection` в обоих порядках: список окна показывает и
   входящие связи, и без проверки окно связи открывается как «новая связь».
4. **Снимок берётся устоявшийся**: у части действий есть отложенное
   продолжение, и снимок на полпути дал бы расхождение от разной скорости,
   а не от разного поведения.

Обход прогоняется тремя частями (`run <страница> <файл> 1|2|3`), потому что
441 снимок в одном сеансе не помещается в память; части сводятся командой
`merge`.

`probe4.mjs` закрывает то, чего не было в прежних наборах: перетаскивание
узла мышью, колесо масштаба (рост, кратность, возврат), СОДЕРЖИМОЕ
вывезенных SVG и PNG (перехватом `URL.createObjectURL`), печатную кожу
(`emulateMediaType('print')`) и узкий экран (700×600: размеры панелей, выход
за край, пересчёт полотна и возврат).

**Раскладка не повторяется от загрузки к загрузке** — сила укладки считает
шаги по реальному времени, поэтому координаты у двух прогонов ОДНОЙ И ТОЙ ЖЕ
страницы разные. Это выяснилось прогоном исходника против себя самого: он
расходился так же, как против сборки. Отсюда два правила в этом приборе:
из вывезенного SVG перед сверкой вычёркиваются все числа (сравнивается
строение, цвета, подписи, порядок — всё, кроме геометрии), а перетаскивание
сверяется допуском «узел уехал за курсором на 120×70 ± 15», а не точным
сдвигом. Вывоз к тому же снимается ДО перетаскивания, иначе в разметку
попадают уже сдвинутые координаты.

`graph_probe.mjs` работает с САМИМ полотном: наведение, одиночный и двойной
клик по узлу, наведение на связь, двойной клик и парный shift-клик под
admin. Три условия, без которых такая проверка врёт, вписаны в него:

1. **Раскладка при загрузке ещё летит** (полная остановка на 15–43 с).
   Ждём остановки и зовём `freezeSimulation` — причём ПЕРЕД КАЖДЫМ
   действием, а не один раз: закрытие окна зовёт `unfreezeSimulation`,
   и узел уезжает из-под курсора между шагами.
2. **Точка выбирается годная**: узел может лежать за краем окна (в первой
   пробе вышло y=1708 при высоте 900) или под панелью. Требуется, чтобы
   `elementFromPoint` дал полотно, а `pickNode` подтвердил попадание.
3. **Правка и shift-клики — только под admin/admin**, и окошко о порядке
   правки после входа надо закрыть: оно лежит поверх полотна.

Ещё две тонкости синтетической мыши. `clickCount: 2` шлёт ОДНО событие с
`detail: 2`, а приложение считает клики само и ждёт два в пределах 300 мс.
И выход за границу элемента браузер вычисляет на СЛЕДУЮЩЕМ входном
событии — если увести курсор одним прыжком и на этом остановиться,
`mouseleave` полотна придёт с запозданием на шаг, и покажется, будто
подсказка не гаснет. У живой мыши поток движений непрерывен, и этого нет.

Сравнивается хеш нормализованной разметки — то есть побайтовое совпадение
вывода, а не «похоже».

## Делегирование: сделано

Переведено всё: в исходнике **224 атрибута** — 96 в статической разметке и 128
в генераторах (счёт `mapping/globals_map_v3.json`, поля `htmlStatic` и
`htmlDynamic`). В собранном дереве встроенных обработчиков **ноль**. Разметка
несёт имя действия, а не имя функции:

```html
<!-- было -->
<div onclick="openUniversalModal('concept', nodes.find(n => n.id === '${c.id}'), 'view')">
<!-- стало -->
<div data-act-click="open-universal-modal" data-a1="${c.id}">
```

В реестре 206 действий (95 из статической разметки, 111 из генераторов).
Тела лежат в `ui/actions-static.js`,
`ui/actions-dyn.js` и `ui/actions-byname.js` — с настоящими ввозами из своих
модулей, без единого обращения к `window`.

Перевод делает `tools/delegate.mjs <дерево> static|dyn`; он же ведёт
`actions_map.json` (имя действия → исходный текст обработчика), по которому
приёмка сверяет обход с прежним перечнем. Без этой карты стороны сравнивать
нечем.

### Что осталось встроенным — ничего

Прежде здесь стояла таблица из шести обработчиков «по делу». Она устарела
дважды, и обе записи проверены заново:

- **2× `onmouseover` + 2× `onmouseout` в `paths/path-ui.js`** — их больше нет **в
  исходнике**. Цвет при наведении отдан стилям (`:hover` у `.path-btn`), и об
  этом там же оставлен комментарий. Атрибутов не осталось ни одного.
- **Пара `onmouseenter`/`onmouseleave` у стрелки пути** — переведена. События
  и правда не всплывают, но делегирование их и не слушает напрямую: признаки
  `data-act-enter`/`data-act-leave` вешаются на `mouseover`/`mouseout`, которые
  всплывают. Смотри `paths/path-ui.js` и `ui/delegation.js`.

Проверяется поиском по дереву: `on(click|change|input|focus|mouse*)=` вне
комментариев даёт **0** совпадений.

**Ложное срабатывание счётчика.** `delegate.mjs <дерево> static` сообщает
«оставлено 1». Это не разметка: образец `ATTR` находит `onmouseover="…"` внутри
**комментария в таблице стилей** — того самого, который объясняет, почему
наведение отдано `:hover`. Комментарий уезжает из `index.html` на шаге
`split_css.mjs`, и в готовой странице его нет. Счётчик стоит научить пропускать
комментарии; поведения это не задевает.

### Ручная статья: `modalActions`

Единственное место, которое механически не переводится. В разметку
подставлялось не данное, а **имя функции и кусок исходного кода**:
`onclick="${saveFn}()"`, а `deleteArg` — это строка `"'c1'"` или
`"'a', 'b'"`. При делегировании имени функции взяться неоткуда, а куску кода
тем более. Поправлено явно в четырёх местах: доводы передаются набором
значений, вызов идёт через таблицу имён (`ui/actions-byname.js`), промах по
имени ругается в консоль.

### Шесть ошибок перевода, найденных на настоящем коде

1. Подстановка бывает не целым доводом, а **частью строки**
   (`'phil-internal-${id}'`) — становится шаблонной строкой.
2. Приставка пространства имён лезла **внутрь строковых постоянных**:
   `toggleSection('rubrics')` → `toggleSection('DATA.rubrics')`. Строки на
   время правки прячутся.
3. Разметка бывает и в обычных строках с **экранированными кавычками**.
4. Второй заход повторно добавлял ввоз в точку входа.
5. Один обработчик встречается и в статике, и в генераторах: имя ему одно,
   тело в реестр — один раз. Это поймал **сам реестр**, заругавшись на
   занятое имя.
6. `event.currentTarget` внутри вызванной функции: при встроенном
   обработчике это сама кнопка, при делегировании — `document`. На время
   действия `window.event` подменяется прослойкой, у которой `currentTarget`
   — элемент с именем действия.

### Чему пришлось научить приборы

Все три прибора теперь понимают **обе записи разом**: идентификатор
концепции лежит либо внутри `onclick`, либо в `data-a2`. Хеши не сравнивают
форму записи обработчика (ни `on*`, ни `data-act-*`, ни `data-a*`), и нигде
не сравнивается **длина** разметки — она меняется от одной лишь формы
записи. И порядок: у элемента, где один обработчик переведён, а другой нет,
очерёдность обхода разъезжалась — теперь обработчики упорядочиваются по виду
события независимо от того, как записаны.

## Моста больше нет

`bridge.js` удалён целиком, установка убрана из точки входа. Счётчик долга
показывает: имён в мосте **0**, записей в `window` вне моста **0**,
обращений `window[выражение]` **0**.

Последнее имя — `handlePathArrowHover` — встроилось так: `mouseenter` и
`mouseleave` не всплывают, но всплывающие `mouseover` и `mouseout` дают ту
же семантику, если отбросить переходы **внутри** элемента (проверка
`el.contains(ev.relatedTarget)`). Держать мост ради одного имени смысла не
было: это тот же глобальный ход, только уже.

Встроенными остались **четыре атрибута**, и мост им не нужен: они не зовут
ни одной функции, а только красят кнопку при наведении
(`this.style.background='#2980b9'`). Их место — в `:hover`, но это правка
стилей, а не долг перед модулями.

**Приборам это стоило собственной оснастки.** Раньше они звали действия
через `window` — и тем держали мост живым. Теперь у переведённой сборки
есть `_probe-rig.js` (модуль, который приборы подключают сами; в работе
приложения не участвует), а у исходника — обычный сценарий, достающий его
лексические объявления: в классическом сценарии `let` и `const` в `window`
**не попадают**, поэтому проверка подсветки узла там прежде вообще ничего
не измеряла.

   выглядит чистым, но `gfxCanvas` — отложенная ячейка. Отбор считается до
   неподвижной точки.
2. **Ввезённому имени присвоить нельзя** — и считать это надо по
   окончательной раскладке. `visibleNodeIds` спека переселила в `core/`, а
   пишет в него `filters/`.
3. **События загрузки уже прошли.** Модуль откладывается по стандарту, и
   `DOMContentLoaded` с `load` к тому времени позади. Симптом был точечный:
   пустые списки в поиске пути. (Обратная сторона того же: разметка при
   вычислении тела УЖЕ ЕСТЬ, и `document.getElementById` в теле законен.)
4. **Модуль, который никто не ввозит, не исполняется** — и не запишет себя
   в `MET`/`VIEWS`. Окно концепции показывало заглушку «вид ещё не
   подключён».
5. **Словарь, читающий `MET` при ввозе**, собирается из `undefined`.
   `METRIC_COVERAGE_FN` — отсюда пропадала кнопка «Нормировать» в пяти видах.
   Ныне мина обезврежена не отложением, а ввозом ради порядка: словарь живёт
   в `stats/coverage.js` и ввозит модули метрик без имён.
6. **Код верхнего уровня уехал в `boot.js`**, и его записи в модульные `let`
   стали межмодульными, даже если спека держала оператор и переменную в
   одном модуле. `tooltipTimeout` был ввезён — и наведение падало на первом
   же движении мыши.
7. **Имя функции может приходить в разметку строкой.** `modalActions` пишет
   `onclick="${saveFn}()"`, и при разборе разметки такого имени не видно
   вовсе. Шесть функций сохранения и удаления не попадали в мост, и любая
   кнопка «Сохранить» давала `ReferenceError`. Мост теперь выставляет и
   функции, чьи имена подставляются строкой. Нашёл это только полный
   обход: прежние наборы звали сохранение напрямую, а не через кнопку.


## Две новые возможности (сделаны после разбивки)

Внесены в одностраничную версию (`tools/patch_orig_persist.py`,
`tools/patch_orig_freeze.py`), и в сборку приезжают **разбивкой** — по одной
реализации на возможность. Получившийся исходник — `source/philosophy_graph_v3.html`,
он же эталон приёмки.

Сперва было иначе: раскладка держалась на диапазонах строк, патчить исходник
до разбивки было нельзя, и каждую возможность приходилось писать дважды. Это
исправлено — см. «Раскладка по именам» ниже.

### Сохранность правок

`fetch` — это чтение; вынос базы в JSON записи не дал и дать не мог. Две
кнопки с общим сериализатором: «💾 Скачать базу» отдаёт шесть файлов теми
же именами, из которых читали; «📂 Сохранить в папку» пишет их через File
System Access — разрешение спрашивается один раз (Chrome и родня).

Сохраняются ТОЛЬКО шесть исходных наборов. Узлы, связи и девять производных
указателей пересобираются из базы; хранить их значило бы завести второй
источник правды.

Признак «есть несохранённое» ставится в единственной точке, через которую
проходит всякое изменение, — `afterDataChange`; уход со страницы с
несохранённым вызывает предупреждение браузера.

### Переключатель заморозки

Правились ИМЕЮЩИЕСЯ `freezeSimulation` и `unfreezeSimulation`, а не заведена
вторая пара поверх: разморозка зовётся из пяти мест, и при второй паре в
коде жили бы ДВЕ разморозки — следующее окно с равной вероятностью позвало
бы «сырую».

Различается не «заморожено или нет», а КЕМ: `'окно'` — как было, `'рука'`
ставит замок, и закрытие окна его не снимает. Пять мест-вызывателей править
не пришлось: они передают источник по умолчанию.

Две развилки закрыты так: когда раскладка уже улеглась, разморозка рукой
снимает замок и честно сообщает «двигаться нечему», а не притворяется
запуском; заморозка прекращает только силу укладки, перерисовку не трогает.

Приборы продолжают замораживать НАПРЯМУЮ, а не кнопкой: если кнопка
сломается, посыплются все проверки графа разом и причина будет неочевидна.
Кнопку проверяет отдельный набор — `probe8.mjs`.

### Что при этом всплыло

- Подсказка кнопки записи обещала в сборке «прямо в папку `data/`», а в
  одностраничной версии «в выбранную папку». Разница была правдивой, но
  сверку ломала; сведена к общей формулировке — обещать в интерфейсе то,
  чего одна из сторон не делает, хуже, чем сказать нейтрально.
- Новые действия не попадали в `actions_map.json`, и обход видел у сборки
  «неизвестное действие». Приёмка сопоставляет стороны по ИСХОДНОМУ тексту
  обработчика, поэтому всякое новое действие обязано попадать в карту.
  Пишет её `delegate.mjs`, и потому новое действие обязано проходить через
  сборку, а не дописываться в дерево руками. (В тексте прежде стояли имена
  `persist.mjs` и `freeze.mjs` — таких программ в наборе нет; правки вносились
  `patch_orig_persist.py` и `patch_orig_freeze.py`, а карту они не трогают.)


## Раскладка по именам вместо строк

Раскладка сущностей по модулям хранится в `decisions/assign_names.json`.
В ней **три раздела**, и читают их разные программы:

| Раздел | Что в нём | Кто читает |
|---|---|---|
| `по_имени` | 742 записи «имя → модуль»; единственный источник домов | `split.mjs` |
| `операторы` | 28 записей «метка + отпечаток → модуль (и имя установки)» | `split.mjs` |
| `новые` | 12 имён — **пометка происхождения, а не дом** | `rename_globals.mjs` |

Раздел **`новые`** сборкой не используется вовсе: у всех двенадцати имён дом
записан в `по_имени` наравне с прочими (девять уехали в `data/save.js`, три в
`render/simulation.js`). Это имена, появившиеся в исходнике **после** того, как
раскладка была составлена впервые, — сохранность правок и заморозка укладки.
Список нужен `rename_globals.mjs`: переименование обязано провести их через
словарь так же, как остальные, иначе после переименования они перестанут
сходиться с исходником. Убрать раздел нельзя, дополнять его при обычной работе
не надо: новое имя требует записи в `по_имени`, а не здесь.

Диапазоны строк сыграли свою роль ровно один раз —
чтобы разложить 730 сущностей впервые.

Замер показал, чем они опасны дальше: после двух вставок в исходник **тридцать
старых сущностей уехали бы не в свой модуль** молча — `freezeSimulation` в
`render/grouping.js`, `confirmWarnings` в `modal/persist.js`. Проверка модулей
этого не поймает: имена сведены, ввозы годные, всё соберётся и заработает —
просто устройство окажется не тем, что записано.

Теперь имя, которого в раскладке нет, **останавливает сборку** с перечнем:
новая сущность требует явного решения, куда её отнести. Операторы, строящие
производные указатели, тоже определяются не перечнем `stmt001…stmt008`, а
положением относительно объявления `links` — привязка к соседу переживает
вставки где угодно ещё.

### Что при переходе всплыло

- **Разметка пишет в глобальные, а разбору этого не видно.**
  `oninput="_pairsMinDegree=+this.value; …"` живёт внутри строки шаблона.
  Такие имена обязаны становиться ячейками `S`: после делегирования тело
  действия — настоящий код в чужом модуле, а присвоить ввезённому имени
  нельзя. Разбивка теперь читает тексты обработчиков разметки.
- **Отбор ячеек стал точнее, и часть имён перестала быть общими.**
  `selectedNodes` больше не в `S`: в него никто извне не присваивает, его
  только пополняют методами. Приборы, искавшие его в прежнем месте, теперь
  смотрят **в оба** — сперва `S`, потом вывоз модуля. Это не подгонка под
  сегодняшнюю раскладку, а признание того, что раскладка меняется.
- **Кириллические имена.** Мои первые патчи ввели `собратьБазу` и
  `замокРаскладки`, тогда как весь файл написан латиницей, а оснастка ищет
  имена по латинскому набору — ввозы для них просто не породились бы.
  Переименовано в `collectData`, `simLockedByHand` и прочее.

## Спецификация модулей

`mapping/module-spec.md` составляется **из собранного дерева**, а не из замысла:
что в модуле лежит, что он вывозит и что ввозит. Прежняя спека описывала
предполагаемую раскладку и потому устаревала при всякой правке; этой
расходиться с действительностью нечем. Пересобирается `tools/gen_spec2.mjs`.


## Единый поиск концепций (сведение пяти меню)

Было: панель поиска пути выпадала вся, но без цветного кружка философа;
легенда, окно концепции и правка связи кружок рисовали, но по пустому запросу
список ЗАКРЫВАЛИ — выбрать глазами было нечего; в правке связи найденное
урезалось шестьюдесятью строками.

Стало: одно устройство по образцу поиска в окне просмотра связи.
`отобратьКонцепции` — единственный отбор и порядок (пустой запрос = показать
всё); `внутренностиСтроки` — единственная строка; `.concept-row` — единственный
облик. Проверено замером: во всех пяти меню 453 строки по фокусу, кружок и имя
философа везде; запрос «иде» даёт одни и те же 15 строк в одном порядке.

**Обработчик пишется буквально, подставляются только доводы.** Первая моя
попытка передавала в строку весь вызов (`onclick="${действие}"`) — делегирование
увидело один довод, действие получило имя `onclick` с телом `el.dataset.a1`, и
строки списка стали мёртвыми; поиск пути с пустым выбором уводил вкладку в
петлю. Это тот же изъян, что был у `modalActions`.

**Проверка меню теперь включает нажатие**, а не только облик: прежняя мерила
разметку — число строк, кружок, имя философа — и всё сходилось при мёртвых
меню.


## Слои и развязка (итог)

Рёбер ввоза снизу вверх — **0** (было 35), кругов в графе ввозов — **0**
(был один на 43 модуля). Порядок слоёв объявлен в `decisions/layers.json`:

```
core/ util/ (0) → data/ state/ (1) → metrics/ (2) →
render/ graph/ filters/ (3) → widgets/ paths/ (4) →
stats/ modal/ (5) → ui/ (6) → boot main (9)
```

Из счёта исключены `data/*.json`, `vendor/*` и `dead.js`: у файла данных и у
поставляемой сборки нет своих ввозов, а склад мёртвого кода не часть устройства.

Проверяется командой `node tools/layers.mjs ввозы`; `node tools/layers.mjs
имя <сущность>` показывает, откуда к ней ходят и куда ходит она, а
`tools/context.py <имя>` — её окружение в одностраничном исходнике с
пояснениями автора.

Шина `core/events.js` держит развороты зависимостей: список событий объявлен,
известить о неизвестном — ошибка, а не тишина; подписки ставит сборка.

**Ввоз — единственное обещание порядка.** Ни `DATA`, ни `S`, ни глобальная
переменная не говорят, вычислено ли уже то, к чему обращаешься. Поэтому там,
где модулю нужен лишь порядок, а не имя, разбивка ставит ввоз без имён:
`import './core/graph-index.js';`. Так же приходят `d3` и имена пространств.

**Правка самой разбивки** — третий род правки, опаснее правки раскладки и
правки исходника, потому что переопределяет всё дерево разом. Порядок работ —
в `doc/build-ops.md`.

## История правок и правила обращения с приборами

Правила — в `readme.md`, раздел «Чему научила приёмка»: там сведено то, что
далось заходами, — прогнать одну сторону дважды прежде чем звать расхождение
дефектом; спрашивать о неизменном, а не о том, что зависит от скорости счёта;
возвращать состояние после каждого действия; проверять новый прибор подложенной
поломкой.

Сами случаи — в отдельном файле `doc/history.md`:
двадцать с лишним заходов, каждый с разбором причины. Здесь остаётся только
устройство сборки, чтобы не смешивать «как оно сделано» с «как оно менялось».
