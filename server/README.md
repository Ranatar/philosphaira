# server/ — серверная часть ΦilosΦaira

**Это РЕШЕНИЕ, а не производное** (readme проекта §12): пересборкой не
восстанавливается, беречь наравне с `decisions/` и `tools/`.

Подробное устройство — в `doc/user_management_system.md` (редакция 3, по
факту построенного). Здесь — только то, что нужно, чтобы поднять и
проверить.

## Порядок слоёв

Снизу вверх; ввоз идёт только вниз, и это проверяет `structure_probe`.

| Слой | Что делает | Правило слоя |
|---|---|---|
| `src/db/` | ВЕСЬ SQL и превращение строк в доменные объекты | `rows[0]` НЕ ПОКИДАЕТ этой папки |
| `src/access/` | роли, права, отношения, заслоны | матрица прав ПОРОЖДАЕТСЯ, а не пишется |
| `src/auth/` | пароли, сессии, второй шаг, привратник | хеш пароля не попадает в доменный объект |
| `src/graph/` | опись шести наборов, чтение графа | выгрузка совпадает с файлами ПОБАЙТОВО |
| `src/commits/` | описание правки, слияние, применение, откат | столкнулось поле — не пишется НИЧЕГО |
| `src/users/` | смена роли, бан, список | допустимые роли считает сервер |
| `src/notify/` | опись типов, складывание, доставка | адресат задан ОПИСЬЮ, не правилами по ролям |
| `src/ws/` | живые соединения и шина между узлами | `Map userId → Set<ws>`: второе устройство не выбивает первое |
| `src/http/` | маршруты, cookie, CSRF, заставы | застава проверяет ПРАВО и только его |

`scripts/` — миграции, перенос графа, первый администратор, работник
исходящих. `probes/` — приёмка.

## Приёмка

`bash accept.sh` — или `bash ../tools/accept.sh` вместе с приложением.

| Слой приёмки | О чём |
|---|---|
| строение | `rows` не покидают `src/db/`; змеиные имена — тоже; первый довод транзакции назван `client`; у каждой миграции есть откат |
| правила | права, отношения, заслоны; матрица сверяется с напечатанной |
| база | накат и откат на чистой базе, мягкое удаление, триггеры, пагинация |
| вход | argon2id, токены с поиском ПО ХЕШУ, отзыв сессий, подтверждение адреса |
| второй шаг | TOTP, коды восстановления, частичная сессия, свежесть |
| управление | смена роли, бан, удаление; **гонка двумя соединениями** |
| перенос графа | шесть JSON → таблица → выгрузка ПОБАЙТОВО |
| коммиты | жизнь до рассмотрения; заслоны стоят в СХЕМЕ |
| слияние | чистые функции: clean / same / conflict |
| применение | на живой базе; версия, столкновения, прямая правка |
| откат | обращающий коммит; история; приращение |
| уведомления | адресаты, широковещание, настройки |
| доставка | падение почты не роняет совершённого |
| соединения | два узла разом, шина, разрыв при отзыве |
| слой HTTP | cookie, CSRF, «кто я» отвечает и гостю |
| страница | НАСТОЯЩИЙ браузер против НАСТОЯЩЕГО сервера |
| продуктовый цикл | весь путь человека ЧЕРЕЗ HTTP: регистрация, письмо, второй шаг, коммит, рассмотрение, откат |
| живое обновление | ПЕРЕХОД в серверный лад и чужая правка на живой странице: координаты, концы связей, массивы симуляции |
| запуск | перенос, первый администратор, гонка двух запусков, точка входа |

Число утверждений в каждом слое печатает сама приёмка — здесь его нет
нарочно: число в тексте устаревает молча.

`product_flow_probe.mjs` ходит ТОЛЬКО ЧЕРЕЗ HTTP — тем же контрактом, что
и человек за браузером. В этом весь смысл: служба, не выведенная наружу,
продуктом не является, и проба, зовущая её напрямую, этого не увидит.
Четыре дыры, найденные им 25.08 (подтверждение почты, заведение второго
шага, правка своего коммита, единый вид ответа у списков), закрыты; после
трёх сошедшихся прогонов подряд он внесён в `accept.sh`.

Знак `⊘` в его выводе значит «возможности нет наружу», `✗` — «утверждение
не сошлось». Путать их нельзя: первое чинится маршрутом, второе кодом,
и итог печатается раздельно. Запускается
руками: `node probes/product_flow_probe.mjs`. Знак `⊘` в его выводе значит
«возможности нет наружу», `✗` — «утверждение не сошлось»; путать их нельзя,
потому что чинятся они по-разному.

ПОЧЕМУ СЛОЁВ ДВА, А НЕ ОДИН. `page_probe` смотрит страницу, УЖЕ вошедшую в
серверный лад; `live_graph_probe` — сам ПЕРЕХОД и то, что за ним следует.
Дефект, стиравший граф начисто и молча при первом же чтении с сервера,
прожил незамеченным именно между этими двумя состояниями: каждое по
отдельности было исправно. **Прибор, не переживающий смены состояния,
смену состояния не стережёт.**

`live_graph_probe` прокручивает `deliverOnce` руками, и это не условность
пробы, а устройство доставки: коммит кладёт извещение в исходящие,
работник публикует его в шину, узел рассылает по сокетам, и только тогда
клиент берёт приращение. **Без запущенного `notify-worker` чужая правка не
доходит до открытых страниц вовсе** — при развёртывании работник нужен
отдельным процессом, иначе живое обновление молча не работает.

## Как поднять

Нужны Node.js, npm и PostgreSQL. Шаги 1–5 делаются ОДИН РАЗ, шаг 6 —
каждый раз.

### 1. База в правильной локали

```
createdb philos --locale=C.UTF-8 --template=template0
```

Голая локаль `C` не годится: единственность логина и почты держится на
`lower()`, а там `lower('ИВАН')` возвращает `ИВАН`. Проверяет `auth_probe`.

### 2. Зависимости

```
cd server && npm install
```

### 3. Окружение

`.env.example` — перечень переменных, а НЕ загружаемый файл: точки входа
читают `process.env` напрямую, `dotenv` в зависимостях нет.

```
export DATABASE_URL='postgres://postgres@localhost:5432/philos'
export MFA_SECRET_KEY="$(node -e "console.log(require('crypto').randomBytes(32).toString('base64'))")"
export BOOTSTRAP_ADMIN_PASSWORD='ваш-длинный-пароль'
```

Ключ второго шага сохраните: потеряете — потеряете все заведённые TOTP.

### 4. Схема

```
npm run migrate
npm run migrate:status
```

Повторный накат безопасен: применяется только то, чего нет.

### 5. Семя графа и первый администратор

```
npm run graph:import
npm run bootstrap-admin
```

Перенос кладёт шесть наборов из `../app/data` в `graph_entities` и
работает ТОЛЬКО на пустом графе: `importSet` пишет с `ON CONFLICT DO
UPDATE`, и повтор перезаписал бы серверные правки семенем. Шесть JSON —
это семя, рабочее состояние живёт в базе. Осознанный повтор —
`ALLOW_GRAPH_REIMPORT=1`.

Первый администратор заводится только при пустой таблице и получает
НАСТОЯЩИЙ пароль. Почта помечается подтверждённой: оператор уже держит
`DATABASE_URL` и ключи — это доверие сильнее письма, и оно снимает круг
«чтобы настроить систему, нужен администратор, а чтобы он получил права,
должна работать почта».

ВТОРОЙ ШАГ САМ НЕ ЗАВОДИТСЯ: секрет должен увидеть человек, вносящий его
в приложение. До этого опасные права срезаны — включая `manage_admins`,
то есть **второго администратора не назначить, пока не заведён TOTP**.

### 5а. Заведение второго шага

```
POST /api/auth/mfa/enroll           → { секрет, ссылка, включён: false }
POST /api/auth/mfa/enroll/confirm   { code } → { включён: true, коды }
```

Оба хода требуют входа и признака CSRF. Имя берётся ТОЛЬКО из сессии: ни
`userId`, ни логин из тела не читаются вовсе — иначе всякий вошедший
заводил бы второй шаг чужой записи и запирал бы её на свой телефон.

Средство оператора остаётся на случай, когда в панель не войти:

```
node scripts/enroll-mfa.mjs [логин]      # умолчание — admin
```

Порядок нарочно двухтактный: секрет показывается, но шаг не включается,
пока не предъявлен код из приложения. Иначе можно запереть себя, сохранив
в базе секрет, который никуда не записан.

Коды восстановления выдаются в конце и видны ОДИН раз. Они одноразовые и
на случай потери аутентификатора; при обычном входе вводится код из
приложения — `submitCode` принимает оба, не различая, и потому код
восстановления легко потратить впустую.

Починка на будущее: два маршрута под `requireAuth`
(`POST /api/auth/mfa/enroll` и `.../confirm`) плюс окно в панели. Службы
готовы, работы немного.

### 6. Запуск

```
npm start                # http://127.0.0.1:8814/
PORT=9000 npm start
```

Один узел поднимает разом страницу, API и живые соединения. Запуск НИЧЕГО
НЕ ГОТОВИТ: не накатывает миграций, не сеет граф, не заводит людей —
молчаливая подготовка при старте есть способ однажды перезаписать рабочую
базу. Останов по `Ctrl+C`: закрываются соединения, потом пул.

При `NODE_ENV=production` включаются cookie только по HTTPS, значит нужен
обратный ставень с TLS.

## Правило, из которого следует остальное

**`rows[0]` не покидает `src/db/`.** Всё, что выходит наружу, прошло через
преобразователь; всё, что входит в службы, — доменный объект. Половина
дефектов первой редакции документа росла из того, что строка базы гуляла
по службам как объект: проверка прав спрашивала `isBanned`, а в строке
лежало `is_banned`, и ответ не зависел от состояния пользователя вовсе.

Правило трижды находило не формальное нарушение, а место, которое стоило
написать иначе. И один раз (беседа 1.2) попытка исполнить его буквально
сделала код ХУЖЕ — см. разбор в `doc/user_management_system.md`.
